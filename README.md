# Teamspace

팀의 프로젝트, 업무, 일정, 문서, GitLab 활동을 연결하는 독립적인 웹 애플리케이션입니다. Jira·Confluence의 핵심 업무와 Plane·Docmost의 입력·보기·문서 편집 방식을 참고합니다. 해당 제품의 서버나 라이선스 키는 필요하지 않습니다.

초기 대상은 20명 이하 한 팀입니다. 복잡한 보안·SSO·기업용 계정 관리는 현재 범위에 포함하지 않습니다. 기존 운영 도구의 데이터는 자동으로 가져오거나 변경하지 않습니다.

## 로컬 실행

Node.js 24 이상이 필요합니다.

```bash
cd /home/sfa/teamspace
npm ci
npm run dev
```

- 웹: `http://127.0.0.1:5173`
- API: `http://127.0.0.1:5181/api/health`
- 최초 실행 시 두 개의 예시 프로젝트와 가상 팀원·티켓·문서를 생성합니다. 실제 팀 운영 데이터가 아닙니다.
- 웹과 API는 기본적으로 루프백 주소에서 실행합니다. 운영 배포·방화벽·리버스 프록시 변경은 하지 않습니다.
- `API_PORT`, `WEB_PORT`로 개발 포트를 바꿀 수 있습니다. API를 단독 실행할 때는 `PORT`를 사용합니다.

## 팀 파일럿 실행

Linux에서 `npm run build:pilot`로 파일럿 번들을 만들고, 절대 데이터 경로를 `TEAMSPACE_DATA_DIR`로 지정해 `npm run start:pilot`을 실행합니다. 웹·API·공동 편집은 기본 `127.0.0.1:5190`의 같은 주소를 사용합니다. 기존 HTTPS 프록시와 공용 접속 키 파일을 지정하면 같은 팀 주소에서 접속할 수 있습니다. `npm run test:pilot`으로 브라우저 흐름과 전체 데이터 복원을, `npm run test:pilot:team`으로 합성 팀원 20명의 동시 사용과 복구를, `npm run test:pilot:access`로 HTTPS 팀 접속을 검증할 수 있습니다. [파일럿 실행과 복원](docs/PILOT.md)

Jira·Confluence 내보내기 파일은 `npm run pilot:rehearsal`로 별도 워크스페이스에서 검토할 수 있습니다. `stage --profile`로 검토한 파일과 원본 인스턴스를 대조하고, `--confluence-findings`로 페이지별 검토 파일을 정확한 Confluence ZIP에 연결할 수 있습니다. 브라우저에서 매핑과 적용을 확인한 뒤 원본과 첨부파일의 해시, 업무·문서와 영수증을 별도 복원본과 비교합니다. [오프라인 이관 리허설](docs/PILOT.md#오프라인-원본-이관-리허설)

팀 설정에서 여러 Jira·Confluence 파일을 순서대로 분석하고, 분석을 끝낸 패키지를 한 번에 이관 매핑에 선택할 수 있습니다. [브라우저 이관 준비](docs/PILOT.md#오프라인-원본-이관-리허설)

## 현재 구현한 흐름

- 프로젝트 개요와 프로젝트 생성, 작업자 선택, 간단한 팀원·이메일 관리
- **팀 개요**에서 모든 프로젝트의 업무 마감·문서 검토·GitLab 활동·당일 시간 배정 조회와 원래 항목 열기
- 상단 팀 알림에서 업무 배정·댓글·문서 검토와 열린 업무의 차단 추가·원인 해소·마감 연기를 확인하고 대상에 이동하거나 읽음 처리
- 차단 알림은 원인 업무를, 마감 연기 알림은 변경 전후 날짜를 표시합니다. 담당자·협력자와 개별·프로젝트 구독자가 함께 받습니다. 마감은 목표 마감일을 우선하고 목표 마감일이 없으면 계획 종료일을 사용합니다.
- **설정 → 업무 마감 알림**에서 담당 업무의 마감 전 1~14일, 당일, 초과 알림을 각각 켤 수 있습니다. 기본값은 모두 꺼져 있습니다. 켜면 서울 날짜를 기준으로 열린 담당 업무를 확인하고, 같은 업무와 마감일의 각 알림을 한 번씩 앱 알림함에 보냅니다.
- 업무 댓글·문서 댓글·문장 선택 댓글에서 `@`로 팀원을 검색해 선택하면 그 팀원에게 멘션 알림을 보냅니다. 알림을 열면 원래 댓글로 이동합니다.
- 문장 댓글을 해결 처리하거나 다시 열고, **미해결**·**해결됨** 목록에서 해당 댓글과 원문을 확인합니다. **댓글 링크 복사**로 선택한 댓글을 바로 열 수 있는 주소를 복사합니다.
- 작성한 티켓·문서 댓글과 문장 댓글의 답글을 수정합니다. 댓글 주소와 원문 위치를 계속 사용하며, 다른 탭에서 먼저 바뀌면 현재 내용과 편집 초안을 함께 확인합니다.
- 업무 상세와 문서 상단에서 개별 구독, 업무 목록·보드에서 프로젝트 업무 구독, 문서 트리에서 프로젝트·팀 공통 공간 구독과 알림함에서 대상 열기
- 티켓 생성·편집·삭제, 기본 9개와 프로젝트별 사용자 정의 유형, 상태·우선순위·담당자·협력자, 계층·라벨·계획일, 댓글·변경 이력
- 티켓 상세에서 **프로젝트 이동**으로 새 키와 대상 프로젝트의 상태·유형·계획을 검토하고 같은 업무를 옮기기
- 문자·숫자·날짜·선택·다중 선택·확인 여부·팀원·URL 필드, 유형별 적용·필수 입력·보관, 값과 이름의 통합 검색
- 목록/보드, 프로젝트별 팀 공통 업무 순서, 필터, 상태 변경, 티켓·문서 통합 검색
- **전체 프로젝트 보드**에서 프로젝트별 실제 상태를 한 화면에 모아 보고 각 프로젝트의 워크플로에 따라 상태 변경
- **내 업무**에서 여러 프로젝트의 담당·협력 업무를 마감 또는 상태 기준으로 묶고, 프로젝트·참여 범위·완료 여부로 좁혀 티켓 열기
- 티켓과 문서의 별표를 선택하고 **즐겨찾기**에서 현재 작업자가 표시한 여러 프로젝트의 항목을 바로 열기
- 티켓별 실제 작업 날짜·시간·메모, 기간·작성자·업무별 작업 시간 보고서
- 프로젝트별 상태·분류·허용 전이·유형별 필수 속성 설정, 검색·형식별 사용자 정의 필드 조건·레이아웃을 공유 보기로 저장
- 상태별 보드 업무 한도와 초과 안내, 필터에 가려진 업무까지 같은 상태에서 열기
- 워크플로 설정에서 특정 상태의 활성 티켓을 새 상태로 일괄 이동하고 필수 입력·자동 배정 결과를 검토
- **보기 링크 복사**로 저장된 목록·보드 공유, 같은 조건으로 **간트에서 열기**와 **업무 보기에서 열기**
- 사이클·모듈·릴리스의 책임자·기간·목표일·상태·진행률 관리, 같은 티켓의 일괄 연결·해제
- 진행 중인 사이클 완료와 미완료 티켓의 다음 사이클·백로그 이월
- 같은 티켓을 편집하는 간트, 화면 내 업무 생성·날짜 입력, 스프레드시트에서 날짜·선후행 연결 붙여넣기와 검토, 막대 이동·기간 조정, FS·SS·FF·SF 업무 연결과 양수·음수 근무일 간격, 여러 일정 이동의 미리보기·일괄 적용·되돌리기
- **전체 프로젝트 간트**에서 소속 프로젝트별 업무 일정과 충돌을 함께 확인하고 실제 업무 날짜를 조정 [전체 프로젝트 간트 사용법](docs/SCHEDULING.md#전체-프로젝트-간트)
- 간트와 티켓에서 선후행 연결과 프로젝트 달력을 반영해 미정 날짜 제안, 차트에서 기존 기간 다시 선택, 같은 프로젝트의 업무를 검색해 선후행 연결과 방향 수정 [날짜 미정 업무 입력](docs/SCHEDULING.md#날짜-미정-업무-입력)
- 시작일이나 종료일과 근무일 수를 입력해 프로젝트 달력으로 반대쪽 날짜 계산 [근무일 수로 날짜 계산](docs/SCHEDULING.md#근무일-수로-날짜-계산)
- 차트에서 목표 마감일을 확인하고, 계획 종료일이 늦거나 미정인 업무의 날짜를 검토·수정 [목표 마감일 검토](docs/SCHEDULING.md#목표-마감일-검토)
- 간트 또는 티켓 상세에서 **새 선행 업무 추가**와 **새 후행 업무 추가**로 날짜를 제안받고 티켓과 연결을 함께 저장 [새 선행 업무 만들기](docs/SCHEDULING.md#새-선행-업무-만들기) · [새 후행 업무 만들기](docs/SCHEDULING.md#새-후행-업무-만들기)
- 티켓 상세의 **간트에서 일정 보기**로 같은 업무 행과 저장 날짜에 이동. 전체 프로젝트 보드에서 열면 현재 필터를 간트에 가져옴
- **간트 HTML 내려받기**로 현재 기간과 화면에 표시된 일정을 공유하거나 인쇄 [간트 보고서 사용법](docs/SCHEDULING.md#간트-보고서-내려받기)
- 티켓 상세에서 프로젝트 간 관련·차단·중복 관계 추가와 양쪽 티켓에서 열기
- 간트와 업무 상세에서 팀원별 시간 배정, 프로젝트 간 겹침 확인과 예약 업무 열기
- 간트의 담당자별 계획 작업량과 가용 시간, 날짜별 초과 확인과 일정 변경 전후 비교
- 프로젝트 간트에서 담당자 과부하를 줄일 업무 날짜를 제안하고, 변경 전후 작업량과 계획 종료일을 검토한 뒤 적용·되돌리기
- 프로젝트 간 작업량과 날짜별 과부하 확인, 팀 공통 근무일·가용 시간 설정, 프로젝트별 배분에서 해당 티켓 열기
- 전체 프로젝트의 작업량을 합산하고 선택한 프로젝트의 업무만 이동하는 과부하 조정, 프로젝트별 종료일 비교와 일괄 되돌리기
- 간트에서 사이클·모듈·릴리스의 기간·목표일 편집, 연결된 업무 보기, 선택 업무 일괄 연결·해제
- 계획과 연결 업무의 달력일·근무일 이동, 미리보기·원자적 적용·응답 재확인·되돌리기
- 프로젝트 업무 달력·휴무/작업 예외, 검토 후 적용하는 자동 일정 제안, 마일스톤과 변경되지 않는 기준 계획 비교·삭제된 기록 보존
- 이정표의 연결 업무에서 계획 종료일 미정이나 이정표 이후로 잡힌 일정을 확인하고 티켓이나 간트의 종료일 칸으로 이동 [이정표 연결 업무](docs/SCHEDULING.md#이정표-연결-업무-확인)
- 저장 일정과 선후행 연결을 바탕으로 프로젝트 예상 완료일·업무별 근무일 여유 계산, 여유 0일 업무와 연결 강조
- 문서 트리와 템플릿, 서식·표·체크리스트·코드·이미지 URL, 슬래시 메뉴, 수동 저장과 버전 충돌 보호, 버전 열람·복구
- 프로젝트·팀 공통 문서의 라벨 편집과 주소로 공유하는 라벨 필터, 프로젝트 전체 통합 검색에서 라벨로 문서 찾기
- 문서 본문에서 프로젝트나 팀 공통 공간의 라벨별 문서 목록 표시와 원래 문서 열기
- 문서에 상태·담당자·날짜 등의 속성을 기록하고 라벨과 공간을 기준으로 모아보는 보고서
- 본문의 하위 문서 목록에서 문서와 공간의 계층 탐색, Confluence 하위 페이지 매크로 이관
- 편집기·이력·검토본·발행본의 **문서 목차**에서 본문 제목으로 이동
- 문서별로 켜는 Yjs 실시간 공동 편집, 접속자·커서·텍스트 선택 영역 표시, 서버 저장 확인·오프라인 재연결과 복구 충돌 보호
- 문서·업무 참조, 최신 원문과 고정 버전의 읽기 전용 포함, 접기 블록, 연결/역참조, 제목·서식·구조를 포함한 이력 비교
- 문서의 **연결**에서 업무 상태와 담당자를 확인하고 같은 문서 위에서 티켓 상세 열기
- 체크리스트 항목에서 후속 티켓을 만들거나 기존 티켓을 연결하고, 항목의 문구나 위치를 바꾼 뒤에도 연결 업무 열기. 연결 당시 발췌는 원래 저장본에서 확인
- 문서 안에서 프로젝트 전체 또는 공유 보기의 업무 목록 표시, 상태·담당자·우선순위별 현황 집계, 원래 티켓 열기
- 문서 전체 또는 선택한 본문의 댓글, 댓글이 달린 당시 원문 읽기, 업무 연결, 문서 Markdown/JSON과 오프라인 문서 트리 ZIP 내보내기
- 프로젝트 상태·마감 현황, 기간별 생성·완료·재개 및 일별 흐름 보고서, 저장한 보고서와 연결된 주간 문서
- GitLab 설정과 읽기 동기화, Push 웹훅으로 브랜치·커밋 연결, MR·파이프라인과 명시적 상태 자동화·미리보기·실행 기록
- GitLab 저장소별 배포 이력과 티켓에 연결된 커밋의 환경별 배포 결과, 시각, GitLab 원본 열기
- 업무 목록·보드에서 열린 MR과 실패·진행 중인 파이프라인을 확인하고 GitLab 조건을 공유 보기로 저장
- GitLab 연결 저장 전 저장소별 조회 결과와 새로 연결되거나 갱신될 티켓 확인
- 티켓 번호가 없는 기존 GitLab MR·파이프라인의 주소 확인과 수동 연결
- Jira에서 옮긴 원래 티켓 키로 기존 GitLab 브랜치·커밋·MR·파이프라인 연결
- 외부 웹훅 수신처·프로젝트/이벤트 범위, 한 번 표시하는 서명 키, 전송 이력·자동 재시도·수동 재시도
- 개인 API 키 발급·회수, 읽기/쓰기·프로젝트 범위·만료 설정과 `/api/v1` 자동화 API로 업무·문서·선후행 연결 관리
- 업무·문서에 Jira 티켓과 Confluence 페이지 연결, 원본 열기와 최신 제목·상태·식별자 조회
- Jira 관리자/검색 XML·CSV·REST/Importers JSON과 Confluence XML/ZIP 원본의 오프라인 분석·보관, 객체·진단·파일 해시 미리보기와 원문 JSON 내려받기
- 분석한 원본의 프로젝트·작성자·유형·상태·필드 매핑, 변환 검토 후 새 프로젝트에 적용, Jira 작업 시간과 원본 이력·관계·첨부 버전 보존
- 이관 영수증에서 현재 대상과 원본 대조, 원래 Jira 키 검색, 문서·댓글·이력·첨부·작업 시간의 작성자 검증, 전체 첨부 버전의 크기·SHA-256 검사와 결과 JSON 내보내기
- 업무·문서와 개별 댓글·첨부의 휴지통과 복원, 첨부 파일 버전 이력, 문서 이미지 삽입, 첨부 바이트를 포함한 JSON 내보내기·가져오기

기능 구현과 검증 결과는 [개발 상태](docs/STATUS.md)를 확인하세요. [일정·간트 사용법](docs/SCHEDULING.md)과 [API 사용법](docs/API.md)도 제공합니다. 제품 전체의 대체 범위와 완료 기준은 [개발 계획](docs/PLAN.md)에 보존합니다.

## 댓글과 첨부파일 복구

티켓이나 문서에서 첨부파일과 내가 작성한 댓글을 휴지통에 보낼 수 있습니다. **휴지통 → 항목 종류**에서 **댓글**이나 **첨부파일**을 선택한 뒤 원하는 항목을 복원하세요. 복원한 항목에서 원래 업무나 문서를 바로 열 수 있습니다. 원래 업무나 문서도 휴지통에 있다면 먼저 그 항목을 복원하세요. 첨부파일을 복원하면 기존 파일 ID와 모든 버전이 돌아옵니다.

티켓 댓글에 붙여넣은 HTTP(S) 주소는 저장한 뒤 새 탭에서 열 수 있습니다. Jira에서 새로 이관한 댓글의 이름 붙은 링크는 `이름 <주소>`로 표시하며 편집과 백업에서 주소를 보존합니다. 이전에 이관하면서 주소가 빠졌다면 해당 댓글 아래 **Jira 원본 링크 확인**을 눌러 보관한 주소를 새 탭에서 열 수 있습니다. 현재 댓글과 원본 링크를 함께 확인할 수 있습니다.

## 티켓 설명의 Markdown 서식

업무를 만들거나 상세에서 편집할 때 **설명 서식**을 **Markdown**으로 고르면 제목·목록·체크리스트·표·코드·링크를 작성할 수 있습니다. **미리보기**에서 본문을 확인한 뒤 저장하세요. 다시 열면 Markdown 설명을 읽기 화면에서 볼 수 있고 **편집**에서 원문을 수정할 수 있습니다. 기존 평문은 입력한 그대로 표시되며 복제할 때 설명과 선택한 서식이 함께 채워집니다.

## 업무 복제

티켓 상세에서 **업무 복제**를 누르면 같은 프로젝트의 새 업무 양식이 열립니다. 저장된 제목·설명·담당자·라벨과 현재 유효한 사용자 정의 값을 확인하고 수정할 수 있습니다. 새 업무는 프로젝트의 초기 상태를 제안하며, 날짜가 필요하면 **원본 일정 복사**를 누릅니다. 저장 후 원본 화면에 새 업무 번호와 **복제 업무 열기**가 표시됩니다. 두 업무는 **관련 업무**로 연결됩니다.

## 업무를 다른 프로젝트로 옮기기

티켓 상세에서 **프로젝트 이동**을 열어 대상 프로젝트를 고릅니다. 상위·하위 업무 또는 선후행 업무도 옮겨야 하면 **연결된 업무 함께 이동**을 선택합니다. 새 업무 키, 대상 상태·유형·계획, 사용자 정의 값과 이동을 막는 이유를 검토한 뒤 적용합니다. 기존 티켓 주소, 댓글, 첨부, 문서와 GitLab 연결은 같은 업무를 가리킵니다. 작업 시간은 티켓과 함께 이동해 대상 프로젝트 보고서에 집계됩니다. Jira에서 가져온 티켓도 원본 링크·상태 이력·업무 관계와 작업 시간을 유지한 채 이동할 수 있습니다. [프로젝트 이동 API](docs/API.md#업무-프로젝트-이동)

## 하위 업무 만들기

상위 티켓 상세에서 **하위 업무 추가**를 누릅니다. 현재 티켓과 같은 프로젝트에 연결되며, 새 업무의 유형·상태·담당자·일정과 필수 속성을 기존 양식에서 입력합니다. 저장하면 상위 티켓의 하위 업무 목록에 새 업무가 추가되고, 작성 중인 상위 티켓 편집과 댓글도 유지됩니다.

목록·보드·간트에서는 **상위 티켓 키**를 눌러 상위 업무를 열 수 있습니다. 상위 업무 행이 현재 검색 조건에서 가려져도 같은 버튼으로 열립니다. 부모 업무 상세에는 직접 연결된 하위 업무의 상태와 완료 수가 표시됩니다.

간트에서 **하위 업무 N개**를 누르면 상위 업무와 그 아래에 이어진 티켓을 모아 봅니다. 각 티켓의 날짜를 그 화면에서 편집하고, 상위 행의 점선으로 하위 업무의 전체 계획 범위를 확인합니다. [하위 업무 일정 보기](docs/SCHEDULING.md#하위-업무-일정-보기)

**상위·하위 일정 함께 이동**에서 일수를 입력하고 변경할 날짜와 제외된 업무를 검토합니다. 여러 단계에 걸친 하위 업무도 포함됩니다. 프로젝트 달력의 근무일 기준으로 옮길 수 있으며, 변경을 적용한 뒤 한 번에 되돌릴 수 있습니다.

## 티켓 사이의 업무 관계

티켓 상세의 **업무 관계 추가**에서 업무 번호나 제목으로 상대 티켓을 찾으세요. 다른 프로젝트의 업무도 연결할 수 있습니다. **관련 업무**는 양쪽에 같은 이름으로 표시되며, 차단과 중복은 각 티켓에서 바라본 방향으로 표시됩니다. 관계를 저장하면 양쪽의 변경 이력에 기록됩니다. 직접 만든 관계는 수정하거나 해제할 수 있고, Jira에서 이관한 관계는 원래 이름의 읽기 전용 항목으로 표시됩니다.

열린 티켓의 **업무 관계 → 중복으로 닫기**에서 원본 업무와 프로젝트가 허용하는 완료·취소 상태를 선택합니다. 원본 연결과 종료 상태를 함께 저장하고 양쪽 티켓에서 상대를 열 수 있습니다. 해당 상태로 바꾸기 위해 필수 입력이나 차단 업무 해결이 필요하면 해당 조건을 확인합니다. 작성 중인 다른 티켓 필드와 댓글은 이어서 편집할 수 있습니다. [중복 업무 종료 API](docs/API.md#중복-업무-종료)

같은 프로젝트의 차단 관계에서는 **일정 연결 검토**로 두 업무의 선후행과 근무일 간격을 설정합니다. Jira에서 옮긴 `Blocks` 관계는 선행·후행 방향을 고른 뒤 간트에 연결합니다. [일정·간트 사용법](docs/SCHEDULING.md#선후행-관계와-자동-제안)

티켓 상세의 날짜 입력 옆 **일정과 연결 편집**에서 이미 입력한 날짜를 불러와 여러 선후행 연결과 함께 검토합니다. 보드나 목록에서 티켓을 연 상태로 저장하고, 상세에서 갱신된 날짜와 연결을 확인하거나 함께 되돌릴 수 있습니다. 작성 중인 업무 내용과 댓글은 이어서 편집할 수 있습니다. [날짜와 연결 함께 편집](docs/SCHEDULING.md#한-업무의-날짜와-연결-함께-편집)

같은 프로젝트의 두 업무에 날짜를 입력하고 간트에서 **차트에서 연결**을 사용하면, 두 업무의 날짜와 선후행 연결을 한 번에 검토하고 저장하거나 되돌릴 수 있습니다. [간트 사용법](docs/SCHEDULING.md#한-업무의-날짜와-연결-함께-편집)

## 프로젝트 업무 순서

프로젝트의 **업무 → 순서 편집**에서 위·아래 버튼으로 티켓 순서를 조정합니다. 검색이나 필터를 적용하면 화면에 보이는 이웃 업무를 기준으로 이동합니다. 보드에서는 대상 카드의 위·아래로 끌어 놓을 수 있습니다. 다른 상태 열의 카드에 놓으면 전이 조건을 확인한 뒤 상태와 순서를 함께 저장합니다.

팀원이 같은 프로젝트를 열면 목록과 보드에 저장된 순서가 표시됩니다. 문서의 업무 목록과 업무 현황에서 펼친 티켓에도 같은 순서가 적용됩니다. 이 순서와 티켓의 긴급·높음 같은 우선순위 값은 별도로 관리합니다. 새 업무와 휴지통에서 복원한 업무는 프로젝트 순서 끝에 추가합니다.

프로젝트의 **업무 → 보드 → 보드 그룹**에서 **담당자별**을 고르면 상태 열을 담당자별로 볼 수 있습니다. 배정을 비우려면 **담당자 미지정**으로 옮기고, 필요한 팀원 줄이 보이지 않으면 **빈 담당자 그룹 표시**를 켜세요. 다른 담당자 줄이나 상태 열로 옮기면 대상 담당자·상태·순서를 함께 저장합니다. 키보드 순서 편집, 업무 상세의 담당자·상태 편집도 사용할 수 있습니다. **현재 보기 저장**으로 담당자별 보드와 필터를 팀에 공유합니다.

## 티켓 이어서 검토하기

업무 목록이나 보드, 간트에서 티켓을 열면 상세의 **이전 업무**와 **다음 업무**로 이어서 검토할 수 있습니다. 처음 상세를 열었을 때의 필터와 표시 순서를 사용합니다. 상태나 담당자를 저장해 현재 티켓이 화면에서 빠져도 같은 순서로 검토를 계속할 수 있습니다.

작성 중인 변경·댓글이 있으면 이동 전에 확인합니다. 상세를 열어 둔 채 브라우저의 뒤로 가기를 누르면 검토를 시작한 보기로 돌아갑니다. 간트와 전체 프로젝트 보드의 필터, 공유 보기 주소도 그대로 사용합니다.

## 여러 상태로 업무 보기

프로젝트의 **업무 → 여러 상태 선택**에서 예를 들어 **진행 중**과 **검토 중**을 고르면 둘 중 하나에 해당하는 업무가 표시됩니다. **현재 보기 저장**을 누르면 목록·보드·간트·문서의 업무 목록과 보고서에서 같은 조건을 쓸 수 있습니다. 단일 상태나 **모든 상태**로 돌아가려면 **상태 필터**에서 선택합니다.

## 공유 보기 정렬

프로젝트의 **업무 정렬**에서 예를 들어 **목표 마감일 오름차순**, **우선순위 내림차순**을 설정한 뒤 **현재 보기 저장**을 선택합니다. 목록, 보드의 각 그룹, 같은 보기로 연 간트와 문서 업무 목록이 지정한 순서로 표시됩니다. 날짜가 비어 있는 업무는 뒤에 표시됩니다. [공유 보기 정렬](docs/API.md#공유-보기의-정렬)

## Jira 필터를 공유 보기로 옮기기

옮겨온 프로젝트의 **업무 → Jira 필터 옮기기**에서 Jira의 고급 검색식을 붙여넣고 **조건 미리보기**를 누릅니다. Teamspace 프로젝트와 현재 상태·유형·팀원·우선순위·라벨 조건, 일치하는 업무를 확인하고 목록 또는 보드 보기로 저장합니다. 저장한 보기는 간트, 문서의 업무 목록과 프로젝트 보고서에서도 열 수 있습니다.

원본 프로젝트와 이관 매핑을 확인할 수 있으면 `assignee = old_login`, `status = "In Review"` 같은 기존 조건을 그대로 붙여넣을 수 있습니다. 현재 Teamspace에서 이름을 바꾼 뒤에도 미리보기에는 연결된 팀원·상태·업무 유형의 현재 이름이 표시됩니다. 원본이나 현재 값에 충돌이 있으면 저장 전에 해당 조건을 검토합니다.

`status IN ("Open", "In Review")`처럼 여러 상태에 해당하는 조건도 옮길 수 있습니다. `(status = Open OR status = "In Review")`처럼 `OR`로 이어진 상태 조건도 같은 방식으로 미리봅니다. [Atlassian JQL 연산자 안내](https://confluence.atlassian.com/jiracoreserver/advanced-searching-operators-reference-939937721.html)

`priority = High`나 `priority IN (11, "Blocker")`는 이관 기록에서 확인한 원본 이름과 ID를 사용합니다. `Highest`와 `Blocker`가 둘 다 **긴급**으로 이관됐다면 그 두 값을 함께 고르는 조건을 옮길 수 있습니다. 미리보기에서 현재 티켓의 우선순위까지 대조합니다. 저장한 보기는 이후에도 현재 Teamspace 우선순위로 조회합니다. [Atlassian JQL 우선순위](https://confluence.atlassian.com/jiracoreserver/advanced-searching-fields-reference-939937719.html#Advancedsearching-fieldsreference-Priority)

`due >= "2026-11-01" AND due < "2026-12-01"`은 목표 마감일이 11월 안에 있는 업무를 고릅니다. 저장하면 목록·보드·간트와 문서 업무 목록에서 같은 조회 조건을 사용합니다. [Atlassian JQL 마감일](https://confluence.atlassian.com/jirasoftwareserver101/advanced-searching-fields-reference-1455427012.html#Advancedsearching-fieldsreference-Due)

`ORDER BY due ASC, updated DESC`를 추가하면 목표 마감일과 수정일 정렬을 검토하고 공유 보기에 저장할 수 있습니다. 원본이 `Rank ASC`나 지원 범위 밖의 정렬을 지정한 경우 **프로젝트 정렬 사용**을 확인해 현재 Teamspace 업무 순서로 저장합니다. [Jira 필터 변환](docs/API.md#jira-필터를-공유-보기로-옮기기) · [Atlassian JQL 필드 안내](https://confluence.atlassian.com/jiracoreserver/advanced-searching-fields-reference-939937719.html)

### Confluence 문서의 Jira 목록 복원

문서 편집에서 보관된 Jira 목록 코드 블록에 커서를 두고 **보관된 Jira 목록 복원**을 누릅니다. 이관한 Jira 프로젝트를 선택하고 **Jira 조건 검토**에서 채워진 검색식과 일치 업무를 확인합니다. **공유 보기 저장**을 누른 뒤 **원본을 업무 목록으로 바꾸기**를 선택하고 문서를 저장합니다. 목록에서 티켓을 열 수 있고, 참조를 새로고침하면 현재 업무와 상태가 표시됩니다.

복원은 JQL 검색식이 직접 들어 있는 목록 매크로에서 지원합니다. URL로 저장한 검색이나 건수 전용 매크로는 원문을 유지합니다. 팀 업무 목록은 현재 보이는 최대 20건과 전체 건수를 표시합니다. 원본의 열 구성과 표시 건수는 검토 화면에서 확인할 수 있습니다. [Atlassian Jira 목록 매크로 저장 형식](https://support.atlassian.com/confluence/kb/how-to-bulk-update-jira-issue-macro-to-point-to-a-different-jira-instance/)

## 업무 목록 CSV

**업무 → 목록 → 현재 목록 CSV**는 현재 프로젝트·검색·필터를 적용한 티켓을 화면과 같은 순서로 내려받습니다. 일부만 필요하면 **일괄 편집**에서 행을 선택하고 **선택 업무 CSV**를 누릅니다. 파일에는 업무 키·제목·유형·상태·우선순위·담당자·라벨과 프로젝트·계획 이름이 들어갑니다. 시작일·종료일·목표 마감일은 각각 확인할 수 있습니다.

일정과 선행 연결을 함께 편집하려면 간트에서 **일정 편집용 TSV 내려받기**를 누르세요. **전체 프로젝트 간트**에서는 여러 프로젝트의 업무를 한 표로 편집할 수 있습니다. 스프레드시트에서 티켓별 시작일·종료일·목표 마감일과 선행 연결을 고치고, 헤더와 행을 **일정 붙여넣기**에서 검토합니다. 날짜 칸을 비워 두면 현재 값을 쓰고, `-`를 입력하면 날짜를 지웁니다. 날짜와 연결을 한 번에 적용하고 되돌릴 수 있습니다. [간트 일정 붙여넣기](docs/SCHEDULING.md#스프레드시트에서-날짜와-업무-연결-붙여넣기)

## 스프레드시트로 새 업무 등록

프로젝트의 **업무 → 목록 → 업무 붙여넣기**에 스프레드시트에서 복사한 셀이나 UTF-8 CSV 텍스트를 헤더와 함께 붙여넣으세요. `제목`은 필수입니다. `설명`, `유형`, `상태`, `우선순위`, `담당자`, `시작일`, `종료일`, `목표 마감일`, `라벨`도 입력할 수 있습니다. 날짜는 `YYYY-MM-DD`, 라벨은 쉼표로 구분합니다. 담당자는 팀원의 이름이나 이메일로 지정하고, 동명이인은 이메일로 구분하세요.

**미리보기**에서 실제 상태·담당자·날짜와 연결을 확인합니다. 한 번에 100개 업무까지 등록할 수 있고, 입력 오류가 있으면 수정한 뒤 다시 검토합니다. `임시 키`가 `prep`인 새 업무를 선행 업무로 삼으려면 `선행 업무`에 `new:prep`을 입력합니다. 이미 만든 업무는 같은 프로젝트의 현재 업무 키를 입력합니다. 한 행에 여러 선행 업무의 연결 유형과 근무일 간격을 지정할 수 있습니다. [새 업무의 선후행 연결](docs/API.md#스프레드시트로-새-업무-등록)

등록하면 표의 순서대로 업무 키를 받고, 입력한 날짜와 연결이 함께 간트에 표시됩니다. 붙여넣기 표에서 지원하는 열 외에 필수 속성이 있는 업무는 **업무 만들기**에서 해당 값을 입력합니다. 기존 업무만 수정할 때는 간트의 **일정 붙여넣기**를 사용합니다.

## 보드 업무 한도

프로젝트의 **설정 → 프로젝트 워크플로 → 상태**에서 각 상태의 **업무 한도**를 입력하고 저장합니다. 빈칸으로 저장하면 해제됩니다. 보드에서는 해당 상태의 전체 업무 수와 한도를 표시하며 하위 업무도 셉니다. 한도에 도달하거나 넘으면 표시가 바뀝니다. 상태 이동에는 기존 전이 규칙이 적용됩니다.

보드 상단의 초과 상태를 누르거나, 일부가 필터에 가려진 열의 **전체 업무 보기**를 누르면 해당 상태의 티켓을 엽니다. 검색어와 저장 보기 조건은 유지됩니다.

## 업무 일괄 편집

프로젝트의 **업무 → 목록 → 일괄 편집**에서 검색·필터를 적용하고 현재 보이는 업무를 최대 100개 선택합니다. 검색이나 필터로 숨겨진 업무는 선택에서 빠집니다. 상태·우선순위·담당자·마감일·라벨을 편집할 수 있습니다. 마감일은 날짜를 지정하거나 지우고, 라벨은 추가할 이름을 쉼표로 입력하거나 선택한 티켓에서 제거할 이름을 고릅니다. 각 티켓은 나머지 라벨을 유지합니다. **변경 미리보기**에서 티켓별 전후 값과 차단 이유를 확인합니다. 담당자를 **직접 지정하지 않음**으로 두면 상태 전이 시 프로젝트의 자동 배정 규칙이 적용될 수 있습니다.

모든 선택 업무가 검증을 통과하면 함께 저장할 수 있습니다. 다른 작업자가 업무나 규칙을 바꾸면 최신 목록에서 다시 미리봅니다. 적용 응답을 받지 못하면 **적용 결과 다시 확인**에서 같은 요청의 결과를 확인할 수 있습니다.

**보고서 → 필드 집계**에서도 행이나 교차표 셀의 업무를 열어 일괄 편집을 시작할 수 있습니다. 같은 그룹의 여러 페이지에서 최대 100개를 선택해 미리보고 적용합니다. 집계나 저장 보기가 바뀌면 최신 결과에서 대상을 다시 선택합니다.

프로젝트에서 티켓을 선택한 뒤 **상위 업무 지정** 또는 **상위 업무 해제**를 고릅니다. 상위 업무는 목록의 현재 필터 밖에서도 업무 키·이전 키·제목으로 검색할 수 있습니다. 티켓별로 현재와 변경 후의 상위 업무를 확인한 뒤 적용합니다. 선택 항목 중 하나라도 자기 자신이나 하위 업무를 상위로 삼게 되면 해당 행에 이유를 표시합니다.

일괄 편집의 **계획 연결**에서 사이클·모듈·릴리스마다 현재 연결을 유지하거나 해제하고, 같은 프로젝트의 다른 계획을 지정할 수 있습니다. 상태 등 다른 업무 변경도 함께 미리볼 수 있습니다. 티켓별로 이전과 새 계획의 이름을 확인한 뒤 적용하고, 계획 화면이나 간트에서 연결된 업무를 확인합니다.

일괄 편집에서 **사용자 정의 속성**을 추가해 여러 필드의 값을 지정하거나 지울 수 있습니다. 상태를 함께 바꾸면 변경 후 업무 양식에 필요한 값을 같은 미리보기에서 확인합니다. 필드를 적용할 수 없는 업무는 미리보기에서 이유를 표시합니다.

## 전체 프로젝트 간트

왼쪽의 **전체 프로젝트 간트**에서 여러 프로젝트의 업무를 같은 기간에 확인합니다. 행에 표시된 프로젝트를 확인하고, **프로젝트 필터**로 범위를 좁힙니다. 업무를 열었다 닫아도 간트 범위는 유지됩니다. 선택한 업무를 근무일 기준으로 함께 이동할 때는 각 프로젝트의 달력을 사용합니다. [상세 사용법](docs/SCHEDULING.md#전체-프로젝트-간트)

**담당자 필터**에서 팀원이나 **미배정**을 고르고 **일정 미정만**을 켜면 시작일이나 종료일이 비어 있는 업무를 모아 볼 수 있습니다. **날짜 입력**으로 빈 날짜 칸을 열고 저장합니다. 두 날짜를 채우면 해당 업무가 목록에서 빠지고, **되돌리기**로 다시 복원할 수 있습니다. 프로젝트·담당자·일정 미정·업무 검색·GitLab 조건은 주소로 공유할 수 있습니다.

**프로젝트 간 차단**에서 다른 프로젝트의 원인 업무를 확인하고, 원인과 차단 대상을 골라 같은 티켓 관계를 저장합니다. 프로젝트 한 개로 좁혀도 다른 프로젝트의 관련 업무를 열 수 있습니다. [프로젝트 간 차단 사용법](docs/SCHEDULING.md#프로젝트-간-차단)

차단 관계의 **프로젝트 간 일정 검토**에서 선행 업무의 새 날짜와 이어진 후행 일정을 함께 검토할 수 있습니다. 같은 선행 업무가 여러 대상을 차단하면 **후행 일정 함께 검토**에서 여러 관계를 고릅니다. 각 프로젝트의 근무일에 맞춰 계산하고 바뀌는 날짜를 한 번에 저장하거나 되돌릴 수 있습니다. [프로젝트 간 후행 일정 검토](docs/SCHEDULING.md#프로젝트-간-후행-일정-검토)

## 간트에서 날짜 일괄 편집

프로젝트 간트 또는 **전체 프로젝트 간트**에서 여러 업무를 선택하고 **일정 일괄 편집**을 누릅니다. 시작일·종료일·목표 마감일마다 유지, 지정, 비우기를 선택합니다. 전체 프로젝트 간트에서는 업무가 속한 프로젝트와 각각의 선후행 경고를 확인합니다. 검토한 날짜는 한 번에 저장하고 **되돌리기**로 함께 복원할 수 있습니다. [상세 사용법](docs/SCHEDULING.md#여러-업무-날짜-일괄-편집)

업무마다 날짜가 다르면 각 행에 직접 입력한 뒤 **입력한 날짜 N건 검토**를 누릅니다. 행별 전후 일정과 선후행 경고를 확인한 다음 함께 저장할 수 있습니다. 미리보기에서 취소하면 입력한 날짜가 남습니다. [날짜 검토와 되돌리기](docs/SCHEDULING.md#수동-일정-변경-검토와-되돌리기)

## 상태 변경 전에 차단 업무 해결

프로젝트의 **설정 → 프로젝트 워크플로 → 허용 전이**에서 해당 경로의 **열린 차단 업무 해결 필요**를 켭니다. 예를 들어 **진행 중 → 완료**에 설정하면 완료·취소되지 않은 직접 차단 업무가 있는 티켓은 완료 처리에서 거절됩니다. 업무 상세의 **차단 업무 보기**에서 원인 티켓과 해당 프로젝트의 상태를 확인합니다. 보드, 목록의 일괄 편집, 업무 API, GitLab 상태 자동화에도 적용됩니다. [워크플로 전이 규칙](docs/API.md#상태-변경의-차단-업무-검증)

Jira 이관 원본에서 연결 대상과 방향을 확인한 차단 업무에도 같은 규칙을 적용합니다. 티켓의 업무 관계에서 **Jira 이관 관계**와 차단 방향을 확인할 수 있습니다.

## 상태 변경 시 목표 마감일 자동 지정

**설정 → 프로젝트 워크플로 → 상태**에서 도착 상태의 **자동 목표 마감일 (근무일)**을 입력합니다. 예를 들어 **검토**에 `2`를 입력하면 목표 마감일을 비워 둔 업무가 검토로 이동할 때 서울 기준 변경일 다음의 두 번째 근무일을 지정합니다. 프로젝트 달력의 휴무일과 추가 근무일을 반영합니다. 기존 날짜와 직접 입력한 값이 우선하며, 일괄 편집에서는 저장 전에 계산된 날짜를 확인할 수 있습니다. 설정 칸을 비우고 저장하면 자동 지정을 끕니다. [상태별 자동 마감일 API](docs/API.md#상태별-자동-목표-마감일)

## 워크플로 상태 일괄 변경

프로젝트의 **설정 → 프로젝트 워크플로 → 상태 일괄 변경**에서 출발 상태와 도착 상태를 고릅니다. 출발 상태에 있는 활성 티켓을 최대 1,000건까지 한 번에 검토합니다. **변경 미리보기**에서 티켓별 차단 이유와 담당자 변경을 보고, 해결할 항목이 없으면 **상태 이동 적용**을 누릅니다. 이 작업은 티켓 상태를 옮기며 워크플로의 상태 정의와 휴지통 자료를 보존합니다.

미리보기 뒤 티켓의 구성이 바뀌거나 검토한 티켓·워크플로·업무 양식·배정 규칙이 갱신되면 다시 미리봅니다. 응답을 받지 못한 경우 적용 결과를 다시 확인할 수 있습니다. [상태 이관 API](docs/API.md#워크플로-상태-일괄-이동)

## 백로그에서 사이클 계획

프로젝트의 **백로그 · 사이클**에서 사이클 미지정 업무와 선택한 사이클을 함께 봅니다. 카드를 끌어 놓거나 **사이클 이동**과 위·아래 버튼을 사용하세요. 이동하면 배정과 순서가 함께 저장됩니다. 티켓의 상태·담당자·일정은 유지됩니다. 다른 작업자가 먼저 변경한 경우 **최신 업무 불러오기**를 누른 뒤 새 위치를 고릅니다. 응답을 받지 못한 경우 **이동 결과 다시 확인**을 사용합니다.

백로그나 사이클 그룹의 **업무 만들기**를 누르면 해당 위치에 배정된 새 업무를 작성할 수 있습니다. 작성 중 사이클이 바뀌면 입력을 유지한 채 등록 위치를 다시 확인합니다. 저장한 업무가 검색 조건에서 숨겨지면 **만든 업무 보기**로 해당 행을 표시합니다. 저장 응답이 끊기면 **업무 생성 결과 다시 확인**으로 같은 티켓을 찾습니다. [백로그 또는 사이클 업무 생성](docs/API.md#백로그-또는-사이클에서-업무-생성)

## 사이클 완료와 업무 이월

**계획**에서 진행 중인 사이클을 열고 **사이클 완료**를 누릅니다. 미완료 업무를 보낼 같은 프로젝트의 사이클 또는 **백로그 (사이클 미지정)**를 선택하고 미리보기에서 이월·완료·취소 업무를 확인합니다. **사이클 완료 적용**을 누르면 선택한 대상으로 미완료 업무를 옮기고 사이클을 완료합니다. 완료·취소 업무는 이전 사이클에 남습니다. 업무 날짜와 상태는 그대로 유지됩니다.

업무의 필수 속성이 사이클 미지정을 막으면 해당 업무에 이유가 표시됩니다. 미리보기 뒤 업무나 계획이 바뀌면 최신 상태로 다시 검토합니다. 적용 응답이 끊기면 **같은 완료 요청 다시 확인**으로 결과를 받습니다. [자동화 API](docs/API.md#사이클-완료와-업무-이월)

**사이클 완료 기록**에서 당시 완료·취소·이월 업무와 이월 대상, 완료한 팀원과 시간을 확인합니다. 여러 번 완료한 사이클은 보고 싶은 기록을 선택할 수 있습니다. **프로젝트 전체**를 선택하면 현재 계획 화면에 없는 사이클의 기록도 볼 수 있습니다. 아직 조회할 수 있는 기록이 없는 예전 사이클에는 빈 상태가 표시됩니다.

## 사이클 진행 추이

프로젝트의 **백로그 · 사이클**에서 선택한 사이클 또는 **계획**의 사이클 상세에서 **사이클 진행 추이**를 엽니다. **업무 수**와 **스토리 포인트**를 전환해 서울 날짜별 전체 범위와 남은 양을 확인합니다. 스토리 포인트는 입력한 값만 합산하며, 미입력 업무 수를 따로 보여줍니다. 날짜를 선택하면 범위 추가·제외, 완료·취소·재개, 추정치 또는 워크플로 분류 변경을 확인하고 현재 남아 있는 업무를 엽니다.

관측을 시작하기 전 날짜는 **미관측**, 수집을 시작하거나 조회한 당일 등 일부 시간만 집계한 날짜는 **부분 관측**으로 표시합니다. 기간은 최대 92일씩 이동합니다. [사이클 진행 추이 API](docs/API.md#사이클-진행-추이)

## 주간 반복 업무

**설정 → 반복 업무**에서 업무 템플릿과 서울 기준 요일·시각을 지정합니다. 담당자를 선택해 매주 배정하거나 나중에 배정할 수 있습니다. 설정 화면에서 다음 실행 시각과 최근에 생성된 티켓을 확인하고 예약을 일시 중지할 수 있습니다. 템플릿이나 필수 입력 때문에 한 회차가 보류되면 실행 기록에서 사유를 확인합니다.

## 상태별 담당자 자동 배정

프로젝트의 **설정 → 상태별 담당자 자동 배정**에서 검토로 넘어간 미배정 티켓을 검토 담당자에게 보내는 규칙을 만들 수 있습니다. 출발 상태와 업무 유형을 비워 두면 각각 모든 상태와 유형에 적용됩니다. 배정 방식을 고른 뒤 **배정 미리보기**로 기존 업무의 예상 결과를 확인하고 규칙을 활성화하세요.

업무 상세에서 상태를 저장하거나, 보드에서 열을 옮기거나, API 및 GitLab 자동화로 상태가 바뀔 때 우선순위 숫자가 가장 낮은 일치 규칙 하나를 평가합니다. 같은 저장에서 담당자를 직접 바꾸거나 비우면 그 값을 사용합니다. **담당자 배정 실행 기록**에서 당시 업무 상태, 담당자와 결과를 확인할 수 있습니다.

## 팀 개요

왼쪽의 **팀 개요**에서 마감 업무와 문서 검토 대기, 최근 GitLab 활동, 당일 시간 배정을 확인합니다. **프로젝트**, **팀원**, **기준일**을 선택하면 주소에 저장됩니다. 목록에서 원래 티켓이나 검토 저장본을 열고, 프로젝트별 **간트 열기**와 **GitLab 활동 열기**로 이동할 수 있습니다.

**일정 미정**, **미배정**, **마감 초과** 등 현황 카드를 누르면 해당 업무가 10개씩 표시됩니다. 티켓에서 담당자를 정하거나, **시작일 입력**·**종료일 입력**으로 간트의 해당 날짜 칸을 바로 열 수 있습니다. 지표와 페이지는 주소에 저장되어 브라우저의 뒤로 가기로 같은 목록에 돌아올 수 있습니다. 선택한 카드를 다시 누르면 기본 마감 목록이 열립니다.

기준일은 서울 시간입니다. 마감은 목표 마감일을 우선하고 계획 종료일을 대신 사용할 수 있습니다. GitLab은 기준일을 포함한 최근 7일간 저장된 티켓 연결을 표시합니다. 업무 상태와 검토 대기 목록은 조회할 때의 상태를 표시합니다.

## 전체 프로젝트 보드

왼쪽 메뉴의 **전체 프로젝트 보드**에서 모든 프로젝트의 업무를 상태 분류별로 봅니다. 카드에 표시되는 프로젝트와 실제 상태 이름을 확인하고, 프로젝트·담당자·업무 검색으로 범위를 좁힙니다. **GitLab 조건**으로 열린 MR, 병합 확인이 필요한 MR, 실패하거나 진행 중인 파이프라인, 연결된 활동이 없는 업무를 찾습니다. 다른 조건과 함께 선택한 뒤 **보드 링크 복사**로 같은 범위를 공유할 수 있습니다. 다른 프로젝트의 업무 상세를 열었다 닫아도 필터가 유지됩니다.

**현재 조건으로 간트 열기**를 누르면 보드에서 보고 있던 프로젝트·담당자·업무 검색·GitLab 조건으로 일정을 확인할 수 있습니다. 브라우저에서 뒤로 가면 기존 보드로 돌아옵니다. [전체 프로젝트 간트 사용법](docs/SCHEDULING.md#전체-프로젝트-간트)

보드를 열어 두면 다른 팀원의 업무 변경과 저장된 GitLab 활동을 약 15초 간격으로 확인합니다. 업무 상세나 상태 변경 창을 닫거나 보드 탭으로 돌아오면 확인을 재개합니다. 지금 확인하려면 **팀 보드 새로고침**을 누릅니다.

카드의 **상태 변경**을 선택하거나 다른 열로 끈 뒤, 해당 프로젝트에서 허용하는 상태를 고릅니다. 같은 창에서 담당자를 지정하거나 **자동 배정 규칙 따르기**를 선택해 상태와 함께 저장할 수 있습니다. 프로젝트 업무 목록의 상태 칸과 프로젝트 보드에서도 같은 창을 엽니다. 다른 필수 입력이나 차단 조건은 티켓 상세에서 확인할 수 있습니다. 카드에는 프로젝트별 업무 순서가 적용되며 상태 변경 후에도 그 순서가 유지됩니다.

## GitLab 동기화 결과

**개발 · GitLab**에서 저장소별 개발 활동 동기화의 최근 완료 결과와 마지막 성공 시각을 확인합니다. 새로고침하거나 다시 접속해도 결과가 남습니다. 실패한 저장소만 이전에 선택한 브랜치·커밋 이력 옵션으로 다시 조회할 수 있습니다. **GitLab 배포 기록**에서는 선택한 저장소의 배포 동기화 결과와 포함 MR 조회 범위를 확인합니다.

## GitLab 프로젝트 웹훅 설정

팀 접속 HTTPS 주소를 갖춘 파일럿의 **개발 · GitLab → GitLab 프로젝트 웹훅 설정**에서 저장소를 골라 점검합니다. 저장된 GitLab 주소와 Teamspace 수신 주소가 표시됩니다. 같은 경로에 기존 웹훅이 있으면 이벤트 종류, SSL 검증, 브랜치 필터와 전송 상태를 확인할 수 있습니다.

수신 주소에 웹훅이 없다면 GitLab에서 해당 저장소의 Maintainer 또는 Owner 권한으로 발급한 `api` 토큰과 Teamspace에 저장한 웹훅 인증 값을 입력한 뒤 **GitLab에 웹훅 등록**을 누릅니다. Push·Merge Request·Pipeline·Deployment 이벤트와 SSL 검증을 켭니다. 배포 이벤트가 꺼져 있는 기존 웹훅은 GitLab 설정에서 **Deployment events**를 켭니다. 응답이 끊기면 **다시 점검**으로 목록을 확인합니다. 실제 인증 수신은 아래 **GitLab 웹훅 수신 확인**에서 볼 수 있습니다. [Teamspace API](docs/API.md#gitlab-프로젝트-웹훅-점검과-등록) · [GitLab 프로젝트 웹훅 API](https://docs.gitlab.com/api/project_webhooks/)

**최근 전송 확인**에서 각 GitLab 전송의 HTTP 응답과 **같은 메시지 인증 수신**을 함께 확인합니다. 일치한 경우 Teamspace 수신 시각과 인증 방식을 표시합니다. 같은 메시지를 재전송하면 각 시도의 HTTP 상태와 함께 동일한 수신 기록이 표시될 수 있습니다. [파일럿 수신 확인 절차](docs/PILOT.md#gitlab-웹훅-수신-확인)

## GitLab 배포 확인

처음 연결할 때나 읽기 토큰을 바꿀 때는 **개발 · GitLab → GitLab 연결**의 **배포 조회 미리보기**를 사용합니다. 확인할 저장소를 고르면 입력 중인 연결로 조회한 배포·성공·포함 MR 건수와 일부 조회 안내를 확인할 수 있습니다. 연결 설정과 배포 기록은 각 저장·동기화 버튼으로 반영합니다.

**개발 · GitLab → GitLab 배포 기록**에서 저장소를 선택해 배포 환경과 상태를 확인합니다. 티켓의 **연결된 GitLab 배포**에는 같은 저장소에서 티켓에 연결된 커밋이나 파이프라인의 SHA, 또는 MR의 확인된 병합·스쿼시 SHA와 일치하는 배포가 표시됩니다. 새 이벤트를 받은 뒤 **배포 새로고침**을 눌러 확인하고, **GitLab 작업 열기**에서 원래 배포 작업으로 이동합니다. 작업 주소가 없는 배포는 커밋 링크를 제공합니다. [GitLab 배포 이벤트](https://docs.gitlab.com/user/project/integrations/webhook_events/#deployment-events)

**배포 이력 동기화**는 선택한 저장소의 최근 배포 50건을 읽습니다. 성공한 배포에는 GitLab이 포함됐다고 확인한 MR도 기록합니다. MR이 이미 Teamspace 티켓에 연결돼 있으면, 여러 MR을 한 번에 배포한 경우에도 해당 티켓에서 같은 배포를 확인할 수 있습니다. [GitLab 배포 API](https://docs.gitlab.com/api/deployments/#list-all-merge-requests-associated-with-a-deployment)

**GitLab 상태 자동화**에서 **배포 성공**을 골라 저장소와 GitLab 환경 이름, 출발·도착 상태를 설정합니다. 환경 이름은 대소문자까지 일치해야 합니다. 미리보기로 조건을 확인하고 규칙을 저장한 뒤 활성화하세요. 활성화 이후 실제로 발생한 성공 웹훅은 같은 저장소의 검증된 커밋이나 포함 MR로 연결된 업무에 적용됩니다. 배포 ID·환경·처리 결과는 설정 화면과 티켓 기록에서 확인합니다.

## GitLab 상태로 업무 찾기

**업무**의 목록과 보드에서 열린 MR, 병합 확인이 필요한 MR, 실패하거나 진행 중인 파이프라인을 볼 수 있습니다. **GitLab 조건**에서 원하는 상태를 고른 뒤 **현재 보기 저장**을 누르면 팀원이 같은 조건을 열 수 있습니다. 저장된 보기를 간트나 문서의 업무 목록·현황에도 사용할 수 있습니다.

파이프라인은 같은 업무·저장소·브랜치에 연결된 최신 실행을 기준으로 표시합니다. **GitLab 활동 새로고침**은 웹훅과 동기화로 이미 저장된 변경을 가져옵니다.

티켓과 **개발** 화면의 열린 MR에서 승인 대기·수정 요청·충돌·파이프라인 등의 병합 상태와 확인 시각을 볼 수 있습니다. **개발 → 지금 동기화**로 GitLab을 다시 조회할 수 있습니다.

연결된 열린 MR에서 **MR 검토 확인 → 미해결 토론 확인**을 누르면 아직 해결되지 않은 토론의 발췌와 확인 가능한 파일 위치를 봅니다. **GitLab에서 토론 열기**로 해당 댓글을 찾아 이어서 검토할 수 있습니다. [MR 토론 조회](docs/API.md#연결된-mr-미해결-토론-확인)

연결된 파이프라인에서 **CI 작업 확인**을 누르면 실패 작업과 수동 실행 대기 작업을 봅니다. 작업 단계, 확인된 실패 사유와 실패 허용 여부를 확인한 뒤 작업 이름을 눌러 GitLab에서 엽니다. [파이프라인 CI 작업 조회](docs/API.md#파이프라인-ci-작업-확인)

티켓과 **개발 · GitLab**에서 **테스트 결과 확인 → 실패 테스트 확인**을 누르면 실패하거나 오류가 난 테스트 이름·스위트·클래스를 볼 수 있습니다. 스택 추적과 출력은 원래 GitLab 파이프라인의 테스트 보고서에서 확인합니다. [Teamspace 테스트 결과 조회](docs/API.md#파이프라인-테스트-결과-확인) · [GitLab 테스트 보고서](https://docs.gitlab.com/ci/testing/unit_test_reports/#view-test-results-in-pipelines)

티켓 상세의 **GitLab 상태 자동화 기록**에서 실행 결과, 목표 상태, 차단 이유와 당시 규칙을 확인합니다. 현재 티켓에서 변경할 수 있는 최근 차단 결과에는 **목표 상태로 편집**이 표시됩니다. 제목·설명·댓글 초안을 유지하면서 상태만 편집기에 채우므로, 필요한 필드를 입력한 뒤 **변경사항 저장**으로 적용할 수 있습니다. 자동화 기록에는 당시 결과가 그대로 남습니다.

티켓의 **GitLab에서 상태 확인**으로 MR 병합·닫기나 파이프라인 성공·실패를 확인하면 활성 규칙과 맞는 **GitLab 상태 변경 제안**을 볼 수 있습니다. **목표 상태로 편집**에서 검토한 뒤 필요한 항목을 채우고 업무를 저장합니다. [GitLab 상태 변경 제안](docs/PILOT.md#티켓에서-gitlab-상태-변경-검토)

## 내 업무와 마감

왼쪽의 **내 업무**에는 상단에서 선택한 작업자가 담당하거나 협력하거나 요청한 업무가 모든 프로젝트에서 모입니다. 기본 화면에서는 열린 업무를 마감 초과, 오늘 마감, 7일 이내, 이후, 기한 없음으로 묶습니다. 브라우저의 현지 날짜를 기준으로 **목표 마감일**을 사용하고, 목표 마감일이 비어 있으면 **계획 종료일**을 사용합니다.

**참여 범위 → 내가 요청한 업무**에서 다른 팀원에게 맡긴 업무의 상태와 일정을 확인합니다. 역할이 겹치는 업무도 목록에는 한 번씩 표시됩니다. **프로젝트**로 범위를 좁히고 **묶는 기준**을 상태로 바꿀 수 있습니다. 처리한 티켓은 **완료·취소 포함**에서 확인합니다. 항목을 눌러 티켓을 확인하고 닫으면 같은 필터로 돌아옵니다.

새 업무의 **요청자**는 기본으로 현재 작업자입니다. 업무를 만들거나 상세를 편집할 때 다른 팀원을 지정하거나 **미지정**으로 저장할 수 있습니다. 기존 기록에 요청자가 없으면 **확인되지 않음**으로 표시합니다.

요청자는 다른 팀원이 업무 상태를 바꾸거나 댓글을 남기면 **팀 알림**에서 확인할 수 있습니다. 상태 알림에는 변경 전후 상태명이 표시되고 댓글 알림에서는 해당 댓글이 열립니다. 업무나 프로젝트를 구독 중이어도 같은 변경의 알림은 한 건이며, 댓글에 멘션되면 멘션 알림을 받습니다.

프로젝트 업무의 **요청자 필터**에서 팀원, **미지정**, **기록 없음**을 고르고 상태나 담당자와 함께 **현재 보기 저장**에 담을 수 있습니다. 같은 보기를 목록·보드·간트, 문서의 업무 목록·현황과 보고서에서 열어 같은 업무를 확인합니다.

## 개인 즐겨찾기

티켓 상세나 문서 상단의 별표를 누르면 선택한 작업자의 **즐겨찾기**에 추가됩니다. 왼쪽 메뉴에서 여러 프로젝트의 티켓과 문서를 모아 보고 열거나 별표를 해제할 수 있습니다. 팀 공통 문서도 추가할 수 있습니다.

휴지통에 넣은 항목은 즐겨찾기 목록에서 숨겨지고, 복원하면 다시 표시됩니다. 영구 삭제하면 해당 항목의 즐겨찾기도 제거됩니다. 즐겨찾기는 전체 워크스페이스 백업에 보관됩니다. [즐겨찾기와 백업 형식](docs/API.md#개인-즐겨찾기)

## 업무와 문서 검색

Jira에서 쓰던 업무 키나 프로젝트를 옮기기 전 티켓 번호를 **통합 검색**에 입력해도 현재 티켓을 찾을 수 있습니다. 결과에 현재 키, 프로젝트와 일치한 이전 키가 표시됩니다. 같은 키에 여러 후보가 나오면 프로젝트와 제목을 보고 원하는 티켓을 고릅니다. 상세 화면에서도 이전 티켓 번호를 확인할 수 있습니다.

기존 Jira 업무나 Confluence 페이지의 주소를 **통합 검색**에 붙여넣으면 이관할 때 저장했거나 **기존 도구 연결**에서 추가한 연결로 현재 업무·문서를 엽니다. Confluence 페이지 ID 주소는 같은 서버·설치 경로와 페이지 ID로 찾습니다. 이관한 문서의 `/display/공간/제목` 주소는 보관된 원본 제목·공간과 페이지 ID 연결에서 찾습니다. Teamspace에서 제목을 바꾼 뒤에도 원래 주소를 검색할 수 있습니다. **전체 검색 결과**에서 프로젝트·문서 라벨 등으로 좁히고 같은 검색을 공유할 수 있습니다. [원본 주소로 업무와 문서 찾기](docs/API.md#원본-주소로-업무와-문서-찾기) · [Confluence 주소 형식](https://support.atlassian.com/confluence/kb/the-differences-between-various-url-formats-for-a-confluence-page/)

GitLab에서 보고 있던 MR·브랜치·커밋·파이프라인의 주소를 **통합 검색**에 붙여넣으면 이미 연결된 티켓을 찾습니다. `group/repo!91`, 정확한 브랜치 이름 또는 전체 커밋 SHA로도 찾을 수 있습니다. 결과에는 일치한 저장소와 참조가 표시되며 **전체 검색 결과**에서 현재 소속 프로젝트로 좁힐 수 있습니다. [GitLab 참조 검색](docs/API.md#gitlab-참조로-티켓-찾기)

상단의 **통합 검색** 또는 `Ctrl+K`·`⌘+K`로 업무나 문서를 찾습니다. **전체 검색 결과**에서 업무·문서, 프로젝트·팀 공통 공간, 문서 라벨을 선택한 뒤 **검색**을 누르면 20건씩 볼 수 있습니다. 검색어 없이 문서 라벨만 선택하는 것도 가능합니다.

정확한 티켓 번호를 먼저 표시합니다. 업무에는 프로젝트와 상태가 표시되고, 문서에는 공간과 상위 문서 경로, 라벨과 본문 발췌가 표시됩니다. 검색 조건과 페이지가 주소에 담겨 같은 검색을 공유할 수 있습니다. 검색 결과에서 티켓을 열고 닫으면 같은 페이지로 돌아옵니다.

### 문서 본문 찾기와 바꾸기

문서 도구막대의 **본문에서 찾기**를 누르거나, 본문에 커서를 놓고 `Ctrl+F` 또는 `⌘+F`를 누르세요. 현재 편집 중인 본문에서 일치한 부분을 강조합니다. **이전 결과**와 **다음 결과**, 또는 `Shift+Enter`와 `Enter`로 이동하면 접힌 구역도 펼쳐집니다. 대소문자 구분을 켤 수 있습니다.

**바꾸기 열기**에서 현재 결과나 찾은 모든 결과를 바꿀 수 있습니다. 빈 값으로 바꾸면 해당 텍스트를 지웁니다. 바꿀 부분에 공통으로 붙은 서식은 유지하고, 모두 바꾸기는 한 번에 되돌릴 수 있습니다. 검색 범위는 현재 문서의 직접 작성한 본문입니다. 포함한 다른 문서의 내용을 찾으려면 원문을 여세요.

## 팀 문서 템플릿

반복해서 쓸 양식을 문서로 만든 뒤 **팀 템플릿으로 저장**을 누르세요. 프로젝트의 양식은 해당 프로젝트에서, 팀 공통 양식은 모든 문서 공간에서 **새 문서 만들기 → 팀 템플릿**으로 선택합니다. 새 문서는 선택한 저장본으로 독립된 초안과 첫 버전을 만듭니다.

문서 화면의 **팀 템플릿 관리**에서 이름을 바꾸거나 보관·복원할 수 있습니다. 양식의 본문을 바꾸려면 같은 공간의 문서에 새 본문을 저장한 뒤 **저장본으로 본문 교체**를 선택하세요. 다른 문서와 티켓 참조는 원래 대상을 가리키며 양식 안의 절 링크는 새 문서의 절로 연결됩니다.

원본 문서가 소유한 첨부 중 본문에 삽입한 이미지와 링크한 파일의 버전을 양식에 보관합니다. 새 문서를 만들면 그 문서의 첨부로 복사합니다. 원본 문서나 원본 첨부를 삭제한 뒤에도 같은 양식으로 새 문서를 만들고, 이미 만든 문서에서 파일을 열 수 있습니다. 외부 웹 주소는 저장된 링크를 사용합니다. 한 파일은 최대 20MiB이며, 한 양식에서 보관하는 파일의 합계는 최대 64MiB입니다.

## 문서 복제

문서 상단에서 **문서 복제**를 선택합니다. 복제본의 제목과 대상 프로젝트 또는 팀 공통 공간, 상위 문서를 고릅니다. **하위 문서 포함**을 켜면 현재 문서와 활성 하위 문서를 함께 복제합니다. **복제 미리보기**에서 범위를 확인하고 **문서 복제 적용**을 누른 뒤 **복제본 열기**로 새 초안을 편집할 수 있습니다.

저장된 본문·아이콘·라벨과 복제 범위의 최신 첨부를 복사합니다. 본문이 직접 가리키는 버전도 복제 범위의 파일이면 함께 복사합니다. 함께 복제한 문서와 절로 향하는 현재 링크는 해당 복제본에 연결합니다. 원본의 미저장 편집과 댓글 초안은 원래 문서에 보관합니다. [복제 범위와 재시도](docs/API.md#문서-트리-복제)

## 문서 트리 순서

문서 상단에서 **문서 순서 편집**을 엽니다. 검색이나 라벨로 문서를 좁힌 상태에서도 같은 공간과 상위 문서 아래의 전체 문서를 볼 수 있습니다. 위·아래 버튼으로 순서를 정한 뒤 **문서 순서 저장**을 누르면 팀의 탐색 트리에 반영됩니다. 다른 작업자가 순서나 구성을 바꾸면 **최신 순서 불러오기**로 확인해 다시 편집합니다. [순서 저장과 백업](docs/API.md#형제-문서-순서)

## 문서 표 편집

표의 셀 안을 누르면 **표 편집**이 나타납니다. 셀을 끌거나 Shift를 누른 상태로 다른 셀을 클릭해 범위를 고릅니다. 모바일에서는 첫 셀에서 **셀 범위 시작**, 마지막 셀에서 **여기까지 선택**을 누릅니다. 키보드에서는 **셀 범위 시작** 후 Shift+방향키로 범위를 넓히고 Shift+Tab으로 표 편집 도구를 엽니다.

**셀 병합**은 선택한 직사각형의 내용을 왼쪽 위 셀에 순서대로 모읍니다. **셀 나누기**를 하면 기존 내용은 왼쪽 위 셀에 남습니다. 첫 행·첫 열 또는 현재 셀의 헤더도 바꿀 수 있습니다. Confluence에서 가져온 표와 공동 편집 문서에서도 같은 도구를 씁니다.

단일 문서 Markdown과 문서 트리 Markdown ZIP에는 복합 표의 헤더·병합 구조가 HTML 표로 저장됩니다. Markdown ZIP으로 다시 가져올 때 확인된 표는 머리글, 병합 셀, 정렬과 셀 안의 본문이 편집 가능한 상태로 복원됩니다. 문서 JSON과 워크스페이스 백업에도 셀 구조가 기록됩니다.

## 문서 연결과 비교

문서 도구모음에서 **2단 구역 삽입** 또는 **3단 구역 삽입**을 선택합니다. 각 단에서 제목·목록·표 등 기존 문서 블록을 편집할 수 있습니다. 좁은 화면에서는 왼쪽 단부터 세로로 표시합니다. **구역 다음 본문으로 이동**(`Ctrl` 또는 `⌘` + `Shift` + `Enter`)으로 구역 밖에서 이어 쓰세요. **다단 구역 해제**는 각 단의 블록을 같은 순서대로 일반 본문에 이어 붙입니다. Confluence에서 옮긴 다단 구역은 지원하는 단 너비 비율과 테두리를 저장합니다.

티켓의 **연결된 문서**에서 제목이나 상위 문서로 검색한 뒤 **문서 공간**으로 좁힐 수 있습니다. 결과에는 팀 공통 또는 프로젝트 공간과 상위 문서 경로가 표시됩니다. 문서에서는 **정보 패널 → 연결**에서 업무 번호·제목과 프로젝트로 기존 티켓을 찾을 수 있습니다. 대상을 고른 뒤 연결을 확인하면 양쪽에 표시됩니다. [자동화 API](docs/API.md#업무와-문서의-직접-연결)

설계나 검증 내용을 새로 작성할 때는 티켓의 **연결된 문서 → 새 연결 문서 만들기**를 엽니다. 공간·상위 문서·기본 또는 팀 템플릿을 고르면 초안과 티켓 연결이 함께 저장됩니다. 티켓과 댓글의 작업 중 입력은 유지됩니다. 새 문서의 제목으로 편집 화면을 열거나 **미리보기**로 저장된 본문을 읽을 수 있습니다. 문서의 **연결된 업무**에서 원래 티켓으로 돌아갑니다. [저장과 재시도](docs/API.md#티켓에서-새-연결-문서-만들기)

도구모음이나 슬래시 메뉴에서 **안내 상자**과 **상태 배지**를 추가할 수 있습니다. 안내 상자는 종류와 제목, 여러 본문 블록을 담습니다. 상태 배지는 문장 안에서 이름과 색을 표시합니다. Confluence에서 지원하는 안내 상자와 상태 배지를 이관하면 편집기와 저장 이력에서도 같은 구조로 읽을 수 있습니다.

본문 위의 **문서 목차**에서 원하는 제목을 선택하세요. 같은 제목이 반복되면 본문에 나오는 순서를 표시하고, 접힌 절의 제목을 선택하면 그 절을 펼칩니다. 편집기에서는 현재 입력 중인 본문을, 이력·검토본·발행본에서는 열어 둔 저장본을 기준으로 목차를 만듭니다.

도구모음의 **문단 서식**이나 슬래시 메뉴에서 제목 1~6을 선택할 수 있습니다. **본문 목차**는 기본으로 제목 1~3을 표시하며, **목차 설정**에서 6단계까지 범위를 지정할 수 있습니다. Confluence 이관과 Markdown ZIP에서 제목 단계와 확인된 절 링크를 보존합니다. [본문 형식과 백업](docs/API.md#제목-단계와-본문-목차)

도구모음이나 슬래시 메뉴에서 **라벨별 문서 목록**을 삽입하세요. **문서 목록 설정**에서 프로젝트 또는 팀 공통 공간, 라벨 일치 방식과 정렬을 고릅니다. 목록에서 원래 문서를 열 수 있고, **참조 새로고침**으로 다른 문서의 라벨 변경을 반영합니다. 이력·검토본·발행본과 Markdown에는 저장한 목록 조건이 표시됩니다.

도구모음이나 슬래시 메뉴에서 **하위 문서 목록**을 삽입할 수 있습니다. 이 문서, 지정한 상위 문서, 이 문서의 공간 또는 지정한 공간을 기준으로 목록을 만듭니다. **하위 문서 목록 설정**에서 표시 단계, 첫 단계의 최대 문서 수와 정렬을 지정합니다. **사용자 지정 순서**를 고르면 문서 트리에서 저장한 형제 순서를 따르고, 순서를 저장한 적이 없는 그룹은 제목순으로 표시합니다. 다른 문서의 이름·위치·순서가 바뀌면 **참조 새로고침**으로 반영합니다. 이력과 고정 저장본에서는 저장 당시 설정을 확인할 수 있습니다. [본문 설정](docs/API.md#하위-문서-목록)

### 문서 속성과 보고서

결정 기록에 `결정` 라벨을 붙이고 본문의 **문서 속성**에 `상태`, `담당자`, `결정일`을 입력해 저장합니다. 속성이 여러 종류면 그룹을 지정합니다. 목록을 둘 문서에 **문서 속성 보고서**를 삽입하고 대상 공간과 라벨, 표시 열을 선택합니다. 같은 이름의 속성이 같은 열에 모이며, 각 행에서 원래 문서를 열 수 있습니다.

표를 최신 상태로 확인하려면 **참조 새로고침**을 누릅니다. 원문에서 숨긴 속성도 보고서에 표시됩니다. 이력·검토본·발행본에서는 저장한 보고서 조건을 확인할 수 있습니다. [본문과 백업 형식](docs/API.md#문서-속성과-보고서)

특정 절을 팀에 공유하려면 목차의 **절 링크 만들기**를 누르세요. 저장이나 공동 편집 동기화가 끝나면 **절 링크 복사**를 누릅니다. 만든 뒤 제목을 수정하거나 제목 블록을 옮겨도 링크는 같은 절을 엽니다. 검토본과 발행본 목차에서 복사한 절 링크는 해당 저장본을 엽니다.

문서 화면의 **Markdown ZIP 내보내기**에서 프로젝트 전체나 팀 공통 문서를 고릅니다. 현재 문서와 하위 문서를 묶으려면 **문서 내보내기 → 문서 트리 ZIP 내보내기**를 사용합니다. 최신 저장본이나 승인·발행본을 선택해 내려받고, 압축을 푼 폴더에서 `README.md`를 열면 문서 트리를 볼 수 있습니다. `manifest.json`에서 첨부파일의 해시와 패키지 밖의 참조를 확인할 수 있습니다.

Teamspace·Docmost의 Markdown ZIP이나 일반 Markdown 폴더 ZIP은 문서 화면의 **Markdown ZIP 가져오기**에서 엽니다. 대상 공간과 상위 문서를 고른 뒤 **ZIP 미리보기**에서 문서 계층, 첨부 수, 변환 안내를 확인합니다. **문서와 첨부 가져오기**를 누르면 새 초안과 첨부가 함께 저장됩니다. 패키지 안에서 확인한 문서·절 링크는 새 문서로 연결됩니다. 응답이 끊겼다면 **적용 결과 다시 확인**으로 같은 적용을 확인할 수 있습니다. [형식과 한도](docs/API.md#문서-트리-markdown-zip-가져오기)

문서를 저장하거나 공동 편집 동기화가 끝나면 검토할 문장을 고르고 **선택한 본문에 댓글 남기기**를 누르세요. 문서의 댓글 패널에서 발췌와 의견을 함께 읽을 수 있습니다. 문서가 수정된 뒤에도 **원문 저장본 열기**로 댓글을 작성하던 당시 본문을 봅니다. 작성 중에 본문 버전이 바뀌면 **본문 다시 선택**을 눌러 의견을 유지한 채 새 원문을 고를 수 있습니다.

회의록이나 결정 문서에서 **연결 → 후속 업무 만들기**를 열면 티켓과 문서 연결을 한 번에 저장합니다. 프로젝트 문서는 해당 프로젝트에 업무를 만들고, 공통 문서는 업무를 둘 프로젝트를 선택합니다. 저장 후 문서의 **연결된 업무**와 티켓의 문서 목록에서 양쪽을 오갈 수 있습니다.

**연결 → 연결된 업무**에서 티켓의 상태·담당자·목표 마감일을 함께 확인하고, 미완료나 종료 업무만 볼 수 있습니다. 목표 마감일이 비어 있는 업무에는 계획 종료일을 표시합니다. 다른 사람이 티켓을 수정했다면 **연결된 업무 새로고침**으로 현재 값을 불러옵니다. 티켓 상세를 문서 위에서 열고 닫아도 제목·본문·댓글 초안이 유지됩니다.

티켓의 **연결된 문서 → 미리보기**를 누르면 현재 저장본과 목차를 티켓 위에서 읽을 수 있습니다. 닫기, Esc, 뒤로 가기로 작성 중인 티켓과 댓글에 돌아옵니다. 미리보기 주소를 다시 열 수도 있습니다. 문서를 편집하려면 **문서 공간에서 열기**를 누르세요.

문서 본문에 **업무 참조**를 삽입해 저장하면 그 티켓의 **본문에서 이 업무를 참조한 문서**에 나타납니다. 다른 프로젝트와 팀 공통 문서도 찾을 수 있습니다. 문서를 직접 연결했다면 **연결된 문서**에 참조 횟수를 함께 표시합니다. 미리보기에서 **본문 참조로 이동**을 누르면 문서 안의 해당 참조를 차례대로 확인할 수 있습니다.

당시의 판단을 남기려면 저장되거나 동기화된 본문에서 문장을 선택하고 **선택한 본문으로 후속 업무 만들기**를 누르세요. 양식에서 인용문을 확인한 뒤 저장하면 티켓 상세의 **결정 근거**에 인용문이 표시됩니다. **원문 저장본 열기**를 누르면 그 문장이 있던 당시 문서를 읽을 수 있습니다. 문서 버전이 바뀌면 새 원문에서 다시 선택하거나 작성 중인 티켓을 일반 문서 연결로 만들 수 있습니다.

이미 티켓이 있으면 **선택한 본문을 기존 업무에 연결**을 누르세요. 프로젝트와 티켓을 고르고 발췌를 확인하면 기존 티켓의 **결정 근거**에 저장됩니다. 이미 연결된 문서에도 발췌를 덧붙일 수 있습니다. 문서의 **결정 근거가 있는 업무만**을 선택하면 발췌가 붙은 티켓과 **원문 저장본 열기**를 찾을 수 있습니다. 문서와 티켓 한 쌍에는 하나의 저장본과 발췌를 연결할 수 있습니다.

티켓에서 결정 근거가 있는 문서 연결을 해제하려면 확인 창에서 승인합니다. 동료가 근거를 추가했다면 이전 화면의 해제 요청을 거절하고 최신 연결을 표시합니다. 작성 중인 티켓이나 댓글은 이어서 편집할 수 있습니다.

프로젝트의 **보고서 → 결정 후속 업무**에서 여러 문서에 남긴 결정과 현재 티켓을 함께 확인합니다. 미완료·종료 상태, 담당자, 티켓 키와 문서 제목으로 찾을 수 있습니다. Jira 원래 키와 프로젝트 이동 전 키는 이 보고서와 문서에서 기존 업무에 결정 근거를 연결할 때 모두 쓸 수 있습니다. 팀 공통 문서와 다른 프로젝트 문서도 해당 프로젝트의 티켓에 연결한 근거가 있으면 표시합니다. **결정 근거 열기**를 누르면 당시 원문에서 선택한 문장이 강조됩니다. 필터와 페이지는 주소에 저장되므로 같은 보기를 공유할 수 있습니다.

결정 후속 업무의 문서 제목을 누르면 현재 문서를 엽니다. 브라우저에서 뒤로 가면 같은 보고서 조건과 페이지로 돌아옵니다.

보고서에서 **일정 미정만**을 켜고 **조건 적용**을 누르면 계획 시작일이나 종료일이 비어 있는 업무만 표시됩니다. **간트에서 날짜 입력**을 누르면 해당 업무의 프로젝트와 첫 빈 날짜 칸이 열립니다. 문서의 **연결** 탭에서도 같은 버튼으로 이동할 수 있습니다.

왼쪽의 **팀 결정 후속 업무**에서는 전체 프로젝트에서 연결된 업무를 마감일 순으로 봅니다. 업무가 속한 프로젝트와 원본 문서의 공간을 각각 확인하고, 프로젝트·담당자·상태·검색을 함께 적용할 수 있습니다. 티켓 상세에서 작업한 뒤 닫으면 같은 조회 조건으로 돌아옵니다.

결정 후속 업무에서 **회의 초안 만들기**를 누르고 제목과 저장할 문서 공간을 고릅니다. 현재 페이지의 티켓 상태·담당자·기한·계획 일정과 당시 결정 발췌가 편집 가능한 문서에 들어갑니다. 문서에서 원본 문서와 티켓을 열거나 같은 조건과 페이지의 현재 보고서로 돌아올 수 있습니다. 다른 팀원이 내용을 바꾸면 제목과 저장 공간을 유지한 채 최신 페이지를 다시 검토합니다. [결정 후속 업무 회의 초안](docs/API.md#결정-후속-업무-회의-초안)

결정 근거나 문장 댓글에서 **원문 저장본 열기**를 누르면 당시 본문에서 실제로 선택했던 부분을 강조합니다. 같은 문장이 반복돼도 기록한 위치로 이동합니다. 원문을 둘러본 뒤 **발췌 위치로 이동**을 누르면 표시한 부분으로 돌아옵니다. 원문에서 Esc를 누르면 본문을 접고 열기 버튼으로 돌아옵니다.

열린 문장 댓글의 **답글**을 누르면 원래 문장 아래에 의견을 남길 수 있습니다. 해결하거나 다시 열면 아래의 답글도 같은 대화에 표시됩니다. 대화 참여자와 멘션한 팀원은 알림에서 새 답글로 이동할 수 있습니다. **답글 링크 복사**로 그 위치를 공유할 수 있습니다. 등록 응답이 끊기면 **답글 결과 다시 확인**으로 이미 저장됐는지 확인합니다.

문서 도구모음의 **업무 참조·문서 참조·문서 포함**에서 대상을 검색해 삽입합니다. 수동 편집은 문서를 저장하고, 공동 편집은 서버 동기화 표시를 확인하세요. 포함한 원문은 읽기 전용이며 **참조 새로고침**으로 최신 저장 내용을 불러옵니다. 현재 문서의 미저장 편집은 유지됩니다. 연결 탭에서는 참조한 문서와 내 문서를 참조하는 문서를 찾을 수 있습니다.

당시의 내용을 보존하려면 도구모음에서 **문서 버전 포함 삽입**을 누르고 원본 문서와 저장본을 선택하세요. 편집기·이력·검토본·발행본에서 **고정 버전 내용 보기**를 누르면 선택한 저장본을 읽기 전용으로 엽니다. 고정 본문 안의 문서 참조와 업무 목록은 저장 당시의 이름으로 표시합니다. 원본이나 첨부가 휴지통에 있어도 저장본이 참조한 해당 문서의 이미지와 파일 버전을 열 수 있습니다. 원본을 영구 삭제하면 고정 본문에 조회 불가 안내가 표시됩니다.

본문에서 넣을 위치를 고른 뒤 **파일 첨부 → 본문에 링크 삽입**을 누릅니다. 이전 버전을 넣으려면 파일의 **버전** 목록에서 같은 동작을 선택합니다. 저장된 링크는 선택했던 파일 버전을 엽니다.

**접기 블록**은 제목과 본문을 함께 보관합니다. 제목에서 Enter로 본문을 편집하고, 접기·펼치기는 내 화면에만 적용합니다. 펼치거나 접는 동작으로 다른 사람의 화면이나 문서 버전은 바뀌지 않습니다.

도구모음의 **업무 현황 삽입**이나 슬래시 메뉴의 **업무 현황**에서 프로젝트·공유 보기·집계 기준을 고릅니다. 그룹별 업무 수와 비율을 확인하고 그룹을 펼쳐 티켓을 엽니다. **참조 새로고침**으로 업무 상태나 공유 보기 변경을 반영할 수 있습니다. 검토본·발행본은 저장 당시의 프로젝트·보기 이름과 집계 기준을 표시합니다. 회의 당시 수치가 필요한 경우 보고서에서 주간 문서를 만들면 해당 날짜 범위의 집계를 보관할 수 있습니다.

이력 탭의 **버전 비교**에서 기준·대상 저장본을 고르거나 **현재 미저장 초안**과 비교합니다. 나란히·통합 보기를 지원하며 서식·표·이미지·참조 대상과 고정 버전 ID의 변경도 표시합니다. 비교는 읽기 전용이고, 복구는 별도 확인 후 새 버전으로 저장합니다.

### 발췌 구역 재사용

공통 절차나 안내를 다른 문서에서 쓰려면 본문을 선택하고 **발췌 구역 삽입**을 누릅니다. 빈 발췌 구역을 추가하고 그 안에 작성할 수도 있습니다. **원본에서 숨기기**를 선택하면 원본의 일반 읽기 화면에서 해당 구역을 숨깁니다. 편집기와 해당 구역을 포함한 문서에서는 계속 사용할 수 있습니다.

다른 문서의 **발췌 포함 삽입**에서 원본을 고릅니다. 발췌 구역의 서식과 본문만 표시하며 **참조 새로고침**으로 최신 원문을 불러옵니다. 포함한 구역의 원본 안내는 숨길 수 있습니다. 검토·발행본에는 저장 당시의 참조가 기록됩니다. Confluence의 블록형 발췌와 발췌 포함을 이관할 때도 같은 기능을 사용합니다. [본문 형식과 API](docs/API.md#문서-발췌), [이관 규칙](docs/PLAN.md)

## 문서 검토와 발행

문서를 저장한 뒤 상단의 **검토·발행**에서 팀원을 검토자로 지정합니다. 여러 명에게 요청할 때는 **검토자 추가**를 누릅니다. 검토자들은 요청 당시의 제목과 본문을 **검토본 불러오기**로 읽고 각자 승인하거나 메모와 함께 수정을 요청합니다. 모든 검토자가 승인하면 해당 저장본이 발행됩니다. 수정 요청이 들어오면 작성자가 새 검토를 요청할 수 있습니다. 요청자는 진행 중인 요청을 철회할 수 있습니다.

이미 발행한 문서를 다시 검토할 때는 **발행본과 비교**를 눌러 마지막 발행본과 요청 당시 검토본의 제목·본문·서식 변경을 확인합니다. 두 저장본을 나란히 보거나 한 열에서 변경 순서대로 볼 수 있습니다. **비교 닫기**로 돌아오면 작성 중인 검토 메모가 남습니다. 다른 사람이 검토 상태를 바꿨다면 **최신 정보**에서 현재 상태를 불러옵니다.

같은 화면의 **발행본 불러오기**에서 읽기 전용 발행본과 발행 메모를 확인합니다. 여러 명이 검토한 발행본에는 검토자별 승인 시각과 메모가 표시됩니다. 초안을 계속 수정하거나 새 검토를 진행하는 동안에도 마지막 발행본을 볼 수 있습니다. 검토본과 발행본에서 최신 원문을 가리키는 포함 블록은 저장된 참조 이름으로 표시하며, 고정 버전 블록은 선택한 본문을 펼칠 수 있습니다.

상단의 **검토함·발행본**에 현재 작업자가 처리할 검토 수가 표시됩니다. **내 검토**에서 배정받은 검토를 열고, **내 요청**에서 보낸 요청과 돌아온 수정 의견을 확인합니다. **발행본**은 현재 프로젝트의 최신 발행본부터 표시하며 전체·다른 프로젝트·공통 문서로 범위를 바꿀 수 있습니다. 검색은 고정본 제목을 기준으로 합니다. 목록에서 열면 해당 버전이 URL에 지정됩니다. 가리키던 버전이 교체되면 화면에서 변경을 알려주고 현재 저장본을 직접 열 수 있습니다.

검토함 주소에 탭·조회 범위·프로젝트·검색어·페이지가 저장됩니다. 주소를 다시 열거나 검토본에서 브라우저 **뒤로 가기**를 누르면 같은 조건의 목록으로 돌아갑니다. 같은 검토본이 목록에 있으면 열었던 행에 초점이 돌아가고, 처리가 끝나 행이 빠졌으면 목록 제목에서 이어서 탐색할 수 있습니다. **내 검토**와 **내 요청**은 주소를 연 작업자의 목록을 표시합니다.

## 보고서와 주간 문서

프로젝트의 **보고서**에서 조회 기간·시간대·업무 유형·담당자를 고릅니다. 현재 업무 현황과 기간별 생성·완료·재개를 각각 확인할 수 있습니다. 수집을 시작할 때 이미 완료된 업무는 현재 현황에 반영되며, 완료 전이는 실제로 관측한 변경부터 집계합니다. 복원으로 이력이 끊긴 기간은 화면에 관측 여부가 표시됩니다.

보고서 화면에서 주간 문서를 만들면 서버가 같은 조건으로 다시 집계하고 결과를 보관합니다. 문서에서 보관본과 관련 업무를 열고 회의 메모를 편집할 수 있습니다.

### 진행 차단 확인

프로젝트의 **보고서 → 진행 차단**에서 미해결 선행 업무, 간트 일정 충돌, GitLab 병합 차단과 최신 실패·수동 실행 대기 파이프라인을 확인합니다. 공유 보기로 대상 업무를 좁힌 뒤 원인별로 조회하세요. 한 업무에 여러 원인이 있어도 전체 건수에는 한 번만 셉니다. 같은 저장소·참조·실행 유형의 새 파이프라인이 성공하면 보고서를 새로고침해 이전 대기가 사라진 것을 확인할 수 있습니다.

목표 마감일이나 계획 종료일이 가까운 업무부터 표시합니다. 다른 프로젝트의 선행 업무도 보고서 위에서 열고 닫을 수 있습니다. 선행 업무를 닫거나 날짜와 연결을 고친 뒤 **진행 차단 새로고침**을 누르면 저장된 상태를 다시 읽습니다.

진행 차단과 릴리스 준비 점검에는 **Jira 이관 관계**로 확인된 선행 업무도 표시합니다. 같은 방향으로 직접 만든 관계가 있으면 그 관계를 기준으로 한 번 집계합니다.

**회의 초안 만들기**를 누르면 현재 보기와 원인 조건의 집계, 보고서 순서상 처음 20개까지의 업무와 차단 근거가 프로젝트의 문서에 저장됩니다. 열린 업무와 원인 업무를 문서에서 바로 확인하고 **회의 메모**를 편집할 수 있습니다. 문서에 기록된 수치와 근거는 작성 당시 값이며, **진행 차단 보고서 열기**는 같은 공유 보기와 원인으로 현재 보고서를 엽니다.

릴리스 계획에서 **릴리스 준비 점검**을 열면 연결된 미완료 업무를 기준으로 봅니다. 시작일이나 종료일이 비어 있거나 업무 종료일이 릴리스 목표일보다 늦으면 기존 차단·일정 충돌·GitLab 조치와 함께 표시합니다. 목표일이 비어 있으면 릴리스 종료일을 사용합니다. 같은 릴리스의 계획과 간트로 이동하거나, 현재 릴리스와 원인이 담긴 주소를 공유하고 회의 문서에 기준일과 근거를 남길 수 있습니다.

## 티켓 양식의 표시 조건

프로젝트의 **설정 → 업무 유형 · 사용자 정의 속성**에서 필드가 표시될 상태와 기준 속성 값을 고를 수 있습니다. 예를 들어 **외부 배포 여부**가 **예**이고 티켓이 **검토** 상태일 때만 **배포 절차 링크**를 표시하고 필수로 지정할 수 있습니다. 상태와 기준 값을 함께 지정하면 두 조건이 모두 맞아야 표시됩니다.

표시 조건을 벗어나도 입력한 값은 보존되며, 조건을 다시 충족하면 양식에 나타납니다. 해당 상태나 전이에서 워크플로가 필수로 지정한 필드는 양식에 표시됩니다.

## 우선순위와 라벨로 업무 찾기

프로젝트의 **업무 → 우선순위·라벨 필터**에서 원하는 우선순위를 고르고, 포함하거나 제외할 라벨을 지정합니다. 포함 라벨을 여러 개 고르면 하나 이상 일치할지 모두 일치할지 선택할 수 있습니다. 라벨 유무만으로도 찾을 수 있습니다. 예를 들어 긴급·높음 업무 중 `배포` 라벨이 있고 `보류` 라벨은 없는 업무를 모아 볼 수 있습니다.

조건을 적용한 뒤 **현재 보기 저장**을 누르면 팀원이 같은 조건을 열 수 있습니다. 저장한 보기는 목록·보드·간트, 문서의 업무 목록·현황, 필드 집계와 진행 차단 보고서에서 사용할 수 있습니다. [자동화 API](docs/API.md#업무-우선순위와-라벨-조건)

## 사용자 정의 필드로 업무 찾기

업무 목록이나 보드의 **필드 필터**에서 비교할 필드를 추가하고, 값이 같음·숫자와 날짜의 범위·선택지 포함·값 유무처럼 필드에 맞는 조건을 고릅니다. 최대 8개 조건을 모두 또는 하나 이상 맞는 업무로 조회합니다. 조건을 적용한 다음 **현재 보기 저장**을 누르면 프로젝트 팀원이 같은 조건을 다시 열 수 있습니다.

**보고서 → 필드 집계**에서 필드와 저장된 보기를 골라 값별 업무 수를 확인할 수 있습니다. 보기 없이 프로젝트 전체를 집계할 수도 있습니다. 각 그룹을 열어 해당 업무로 이동하고, 숫자 필드는 최솟값·최댓값·평균·합계를 함께 확인합니다.

행과 **비교 기준** 각각에 상태·담당자 같은 기본 필드나 팀의 사용자 정의 필드를 고를 수 있습니다. 예를 들어 **원인 유형**과 **영향 범위**를 교차한 뒤 셀을 누르면 두 값이 모두 해당하는 업무가 열립니다. 다중 선택 업무는 해당하는 행과 열에 각각 들어가고, 전체 업무 수는 업무마다 한 번만 셉니다.

**합계 항목**에서 스토리 포인트, 계획 작업 시간 또는 사용자 정의 숫자 필드를 고르면 업무 수와 함께 행·열·교차 셀의 합계를 확인할 수 있습니다. 예를 들어 담당자와 상태로 묶어 계획 작업 시간을 분 단위로 합산합니다. 셀을 열면 각 업무의 값과 값 없음을 구분해 보여줍니다. 합계 항목은 공유 링크와 이름으로 저장한 집계에 함께 남습니다. [업무 필드 집계](docs/API.md#업무-필드-집계)

**요청자**를 행이나 비교 기준으로 선택하면 상태별 요청 건수를 확인할 수 있습니다. **미지정**과 **기록 없음**은 별도 그룹으로 표시되며 각 그룹에서 원래 업무를 열 수 있습니다.

업무 화면에서 저장된 보기를 선택한 뒤 **필드 집계에서 열기**를 누르면 그 보기로 집계 범위를 지정합니다. 기준을 골라 조회하고 **필드 집계 링크 복사**를 누르면 팀원이 같은 조건으로 최신 결과를 열 수 있습니다. 보고서의 **저장한 업무 보기 열기**로 해당 목록이나 보드에 돌아갑니다.

다시 볼 집계를 조회한 뒤 **현재 집계 저장**을 눌러 이름을 붙입니다. 팀원이 **저장한 필드 집계**에서 이름을 열면 프로젝트나 공유 업무 보기의 현재 조건으로 다시 계산합니다. 편집에서 이름을 바꾸거나 새로 조회한 조건으로 교체할 수 있습니다. 원래 공유 보기나 필드가 삭제된 집계도 목록에서 찾아 조건을 고칠 수 있습니다. [저장과 복원](docs/API.md#이름으로-저장한-필드-집계)

## 실제 작업 시간

티켓 상세의 **작업 시간**에서 작업한 날짜, 시간과 분, 메모를 저장할 수 있습니다. 프로젝트의 **보고서 → 작업 시간**에서 날짜 범위와 작성자를 고르면 합계와 날짜·작성자·업무별 내역을 확인할 수 있습니다. 티켓의 예상 소요 포인트는 기존 방식으로 사용하고 실제 작업 시간을 합산합니다. 새 기록은 분 단위로 입력하며 Jira에서 이관한 기록은 원본의 초 단위까지 표시합니다.

## 데이터와 연결 설정

기본 데이터 디렉터리는 `data/`이며 `TEAMSPACE_DATA_DIR`로 바꿀 수 있습니다. DB, WAL, GitLab 자격 증명 암호화 키와 원본 분석 파일은 모두 Git 추적에서 제외합니다. DB를 파일 복사로 백업할 때는 API를 종료하거나 SQLite의 일관된 백업을 사용하세요. 자격 증명 복구에는 같은 디렉터리의 `.credential-key`도 필요합니다. 분석 원본은 `data/legacy-imports/`에 비공개 파일로 보관합니다. 이 폴더와 분석 DB 기록은 자체 JSON 백업에 포함되지 않으며, 자체 백업 가져오기 후에도 유지합니다. 필요 없어진 원본은 분석 카드에서 별도로 삭제하세요. 원본 패키지·이력까지 보존하려면 DB와 이 폴더도 함께 일관되게 백업해야 합니다. 원문 미리보기도 현재 신뢰하는 로컬 관리 브라우저 범위에서 접근합니다.

자체 JSON 내보내기는 연결 토큰과 API 키를 제외하며, 가져오기가 성공하면 기존 API 키를 모두 회수하고 자동화 규칙은 비활성으로 복원합니다. 외부 웹훅 수신처·비밀값·전송 기록은 자체 JSON에서 제외하며 가져오기 시 초기화합니다.

상단 팀원 선택은 변경 이력의 작업자를 정하며 인증을 제공하지 않습니다. 실제 팀 운영에 공개하기 전 실행 환경과 단순 접근 제한 방식을 결정해야 합니다.

GitLab은 화면에서 주소·숫자 프로젝트 ID·읽기 토큰을 설정한 후 명시적으로 동기화합니다. 실제 GitLab 자격 증명을 자동 발견하지 않습니다. 토큰은 서버에 암호화해 저장하며 브라우저에 재전송하지 않습니다. 동기화는 GitLab의 업무·저장소 내용을 수정하지 않습니다.

기존 개발 이력을 연결하려면 개발 화면의 **기존 브랜치·커밋 포함**을 켜세요. **연결 미리보기**로 티켓 후보를 확인하고 **지금 동기화**를 누르면 저장한 GitLab 설정으로 조회합니다. 브랜치 이름이나 커밋 제목·메시지에 있는 티켓 키를 찾습니다. [GitLab 이력 동기화](docs/API.md#mr-생성-전-브랜치커밋)

일부 GitLab 저장소에 접근할 수 없어도 조회를 완료한 저장소는 반영합니다. 동기화 결과에서 실패 단계와 원인을 확인하고 해당 저장소만 다시 시도할 수 있습니다.

티켓 번호가 없는 기존 MR이나 파이프라인은 티켓 상세의 **GitLab 링크 추가**에서 저장소를 고르고 페이지 주소를 붙여넣으세요. 실제 항목을 조회해 연결하고, **수동 연결 다시 확인**으로 최신 상태를 가져올 수 있습니다. 필요하면 티켓에서 수동 연결을 해제할 수 있습니다. [수동 GitLab 연결](docs/API.md#gitlab-수동-연결)

새 개발을 시작할 때는 티켓의 **GitLab 브랜치 만들기**에서 저장한 저장소를 선택하세요. 기본 이름은 대문자 티켓 키를 포함한 `feature/TEAM-12` 형식입니다. 기준을 비우면 저장소의 기본 브랜치를 사용합니다. **브랜치 미리보기**에서 저장소 경로와 기준 커밋 SHA를 확인하고, 해당 저장소에서 브랜치를 만들 수 있는 GitLab API 토큰을 한 번 입력해 생성합니다. 같은 이름이 이미 있으면 GitLab 주소를 표시하며 필요한 경우 **GitLab 링크 추가**로 연결할 수 있습니다. [GitLab Branches API](https://docs.gitlab.com/api/branches/#create-repository-branch)

응답을 잃었거나 만든 브랜치의 연결이 보류됐을 때는 **생성 결과 다시 확인**을 사용하세요. GitLab에서 같은 이름과 검토한 커밋 SHA를 확인한 뒤 티켓에 연결합니다. 미확인 요청은 재시작 뒤에도 조회로 확인합니다. 브랜치 연결 이후의 티켓 자동 전이는 인증된 MR·파이프라인·배포 이벤트의 기존 규칙을 따릅니다. [티켓에서 GitLab 브랜치 만들기](docs/API.md#티켓에서-gitlab-브랜치-만들기)

Jira 이관 후에는 개발 화면에서 저장소별로 대상 Teamspace 프로젝트와 Jira 원본을 선택하세요. 그 저장소의 활동은 선택한 프로젝트에서 현재 티켓 키와 보관한 Jira 키를 찾습니다. 같은 키가 두 티켓을 가리키면 연결을 보류하고 미리보기에 표시합니다. 연결을 저장하면 티켓과 개발 화면에서 해당 Jira 원본 키를 확인할 수 있습니다. [원본 키 연결](docs/API.md#이관한-jira-키로-연결)

GitLab 프로젝트의 **Push events** 웹훅을 켜고 `feature/TEAM-12-login`처럼 브랜치 이름에 티켓 번호를 넣습니다. 푸시가 도착하면 티켓의 **GitLab**에서 브랜치와 수신한 커밋을 열고 마지막으로 확인한 SHA를 볼 수 있습니다. 커밋 메시지에 티켓 번호가 없으면 브랜치 번호로 연결됩니다. 브랜치를 삭제한 뒤에도 티켓에서 브랜치 이름과 기존 커밋을 확인할 수 있습니다. [GitLab 웹훅 이벤트](https://docs.gitlab.com/user/project/integrations/webhook_events/#push-events)

## Jira·Confluence 원본 연결

업무 상세나 문서 **연결** 탭의 **기존 도구 연결**에서 원본 주소를 추가합니다. **원본 열기**로 기존 시스템을 열 수 있습니다. 서버에 해당 서비스 주소를 설정하면 **원본 정보 조회**에서 제목·상태·식별자와 원본 수정 시각을 확인합니다. 링크는 업무나 문서를 복원하면 다시 표시됩니다. [연결 설정과 지원 주소](docs/PILOT.md#jiraconfluence-원본-조회)

Jira·Confluence 내보내기 파일을 이관할 때 패키지별 원본 기본 주소를 입력하면 새 업무·문서에 원본 링크가 함께 저장됩니다. 이관 적용 전에 주소 예시와 연결·미연결 건수를 확인할 수 있습니다. [오프라인 이관 절차](docs/PILOT.md#오프라인-원본-이관-리허설)

이관 매핑을 JSON으로 저장하면 같은 원본 파일을 다시 분석한 뒤에도 팀원·상태·필드와 제외 항목 설정을 이어서 검토할 수 있습니다. [오프라인 이관 절차](docs/PILOT.md#오프라인-원본-이관-리허설)

새 Jira 프로젝트를 이관할 때 **Jira 워크플로 매핑 → 허용 전이 직접 지정**에서 새 업무의 초기 상태와 허용 방향을 정할 수 있습니다. 내보내기에 없는 상태는 직접 추가합니다. 이관된 업무는 매핑한 현재 상태로 들어오며, 선택한 전이는 실제 적용 전에 미리보기에서 확인합니다. 원본의 조건·검증기·후처리는 확인 항목을 참고해 프로젝트 설정에서 별도로 검토합니다. [워크플로 이관](docs/API.md#새-jira-프로젝트의-워크플로-지정)

미리보기의 **Jira 이력에서 확인한 전이**에서는 각 방향으로 이동한 원본 업무 수를 봅니다. 사용할 방향을 선택해 **선택한 전이를 매핑에 추가**를 누르면 기존에 직접 지정한 방향과 함께 편집할 수 있습니다. 새 미리보기에서 최종 워크플로를 확인한 뒤 적용합니다.

이전에 옮긴 Jira 프로젝트의 새 내보내기 파일을 분석하고, **이관 방식 → 기존 프로젝트에 새 Jira 업무 추가**를 선택할 수 있습니다. 현재 Teamspace 프로젝트의 상태·유형·필드에 매핑한 뒤 새 업무와 이미 이관한 기록의 건수를 미리 확인합니다. 새 업무에는 다음 Teamspace 키를 부여하며, 기존 부모와 연결되면 그 업무를 이어서 참조합니다. 이미 옮긴 업무에 대한 새 원본 내용은 이관 영수증에서 읽을 수 있습니다. [추가 이관 API](docs/API.md#기존-프로젝트에-새-jira-업무-추가)

이미 옮긴 티켓도 갱신하려면 **기존 Jira 업무 변경분 반영**을 선택하세요. 미리보기에서 반영할 원본 값과 팀의 편집을 보존할 필드를 확인합니다. Jira에서 빠진 필드는 현재 값을 사용합니다. 적용은 현재 Teamspace 워크플로와 티켓 버전을 확인합니다. [Jira 변경분 반영 API](docs/API.md#이미-이관한-jira-업무에-원본-변경분-반영)

이전 Jira REST 이관에서 빠진 마감일은 티켓의 **원본 기록 → Jira 마감일 복구**에서 비교할 수 있습니다. 현재 값이 비어 있고 팀에서 마감일을 바꾸지 않은 근거가 있을 때 **복구 적용**으로 보존 원본의 날짜를 저장합니다. [보존 원본의 Jira 마감일 복구](docs/API.md#보존-원본의-jira-마감일-복구)

새 내보내기에 상위 업무가 확인되면 **상위 업무** 행에서 현재 업무와 제안 업무의 키·제목을 비교합니다. 이전 버전에서 분석한 원본은 상위 업무를 검토하기 전에 다시 분석하세요.

**기존 Jira 업무의 사용자 정의 속성 변경분 반영**을 선택하면 현재 프로젝트 속성에 매핑한 원본 값을 따로 비교할 수 있습니다. 보내지 않은 값은 유지하고, Jira에서 명시적으로 비운 값은 미리보기에 표시합니다. 같은 내보내기에서 기본 필드를 먼저 반영한 뒤 사용자 정의 속성을 검토할 수도 있습니다. [Jira 사용자 정의 속성 이관 API](docs/API.md#이미-이관한-jira-업무에-사용자-정의-필드-변경분-반영)

**기존 Jira 업무에 댓글과 작업 시간 기록 추가**를 선택하면 새 원본 기록을 같은 티켓에 추가할 수 있습니다. 원본 작성자를 팀원으로 매핑하고 미리보기에서 추가 건수를 확인합니다. 기존 기록과 삭제 이력을 보존하며, 작업 시간은 원본의 초 단위 값을 유지합니다. [Jira 댓글·작업 시간 이관 API](docs/API.md#기존-jira-업무에-댓글과-작업-시간-추가)

**기존 Jira 업무에 첨부파일 추가**를 선택하면 이전에 옮기지 않은 원본 ID의 파일을 같은 티켓에 추가합니다. 미리보기에서 추가 건수를 확인할 수 있습니다. 패키지의 파일 크기와 SHA-256을 확인하고, 새 파일은 별도의 첨부파일로 보관합니다. [Jira 첨부파일 이관 API](docs/API.md#기존-jira-업무에-첨부파일-추가)

**기존 Jira 업무 사이의 새 관계 추가**를 선택하면 같은 Jira 원본 프로젝트에서 옮긴 두 티켓에 새 관계를 추가할 수 있습니다. 미리보기에서 양쪽 티켓과 원본 관계를 검토합니다. 기존에 같은 관계가 확인되면 건너뛰고, 대상을 증명할 수 없는 관계는 원본 기록에서 확인할 수 있습니다. 이관한 차단 관계는 티켓에서 열어 간트의 선행·후행 연결을 검토하세요. [관계 이관 API](docs/API.md#기존-jira-업무-사이의-관계-추가)

이전에 옮긴 Confluence 공간의 XML ZIP을 같은 원본 인스턴스 식별값으로 분석합니다. **이관 방식 → 기존 프로젝트에 새 Confluence 문서 추가**를 선택하면 새 문서·이력·댓글·첨부를 같은 프로젝트에 넣을 수 있습니다. 이미 옮긴 문서와 편집 내용은 보존합니다. 새 문서는 같은 공간에서 확인한 기존 상위 문서와 본문 참조를 사용할 수 있습니다. [Confluence 추가 이관 API](docs/API.md#기존-프로젝트에-새-confluence-문서-추가)

첫 이관과 새 문서 추가에서 원본 페이지에 연결된 공개 전역 라벨을 확인해 문서 라벨로 옮깁니다. 개인 라벨과 공개 여부를 확인하기 어려운 라벨은 분석 원본에 보존합니다. 이미 옮긴 문서의 라벨은 변경분 반영에서 검토할 수 있습니다.

원본 공간의 페이지만 조회하는 **라벨별 내용** 매크로는 이관 범위를 확인한 뒤 편집 가능한 목록으로 변환합니다. 변환 뒤에는 대상 Teamspace 프로젝트의 문서와 라벨로 목록을 갱신합니다. 여러 공간의 조건이나 지원 범위를 벗어난 CQL은 이관 진단과 함께 원문으로 보존합니다. [Confluence 라벨별 내용 매크로](https://confluence.atlassian.com/doc/content-by-label-macro-145566.html)

**기존 Confluence 문서 변경분 반영**을 선택하면 이전에 옮긴 문서의 제목·본문·라벨·상위 문서를 비교합니다. **상위 문서** 행에서 현재 경로와 제안 위치를 확인하세요. 이전 버전에서 분석한 XML ZIP은 위치를 검토하기 전에 다시 분석합니다. 팀이 편집한 필드와 참조·첨부를 확인할 수 없는 본문은 보존합니다. 본문을 갱신하려면 공동 편집 참여자가 나간 상태에서 검토하고 적용합니다. 반영한 결과는 새 문서 이력에 저장됩니다. [Confluence 변경분 반영 API](docs/API.md#이미-이관한-confluence-문서에-원본-변경분-반영)

**기존 Confluence 문서에 첨부와 버전 추가**를 선택하면 기존 문서에 새 원본 파일과 확인한 새 버전을 이관합니다. 본문이 가리키는 원본 버전을 확인할 수 있으면 이미 저장한 파일을 재사용합니다. 팀이 직접 올린 최신 파일과 이전 본문에 고정된 파일도 보존합니다. [Confluence 첨부 이관 API](docs/API.md#기존-confluence-문서에-첨부와-버전-추가)

Confluence의 PDF·Word·Excel·PowerPoint 미리보기 매크로는 소유 페이지와 파일을 확인하면 본문 다운로드 링크로 옮깁니다. 대상을 확인하기 어려운 매크로는 미리보기 진단과 원본 코드 블록에서 확인할 수 있습니다. [Confluence 저장 형식의 파일 매크로](https://confluence.atlassian.com/spaces/CONF53/pages/411108832/Confluence%2BStorage%2BFormat%2Bfor%2BMacros)

**기존 Confluence 문서에 댓글과 이력 추가**를 선택하면 이전에 옮기지 않은 원본 댓글과 버전을 미리 보고 추가할 수 있습니다. 팀이 편집한 현재 문서와 댓글은 그대로 유지됩니다. 문서 이력에서 Confluence 원본 버전을 열어 비교하거나 현재 문서의 새 저장본으로 복구할 수 있습니다. [Confluence 댓글·이력 이관 API](docs/API.md#기존-confluence-문서에-댓글과-이력-추가)

Confluence 패키지에 `/wiki` 같은 설치 경로를 포함한 원본 기본 주소를 입력하면, 본문의 페이지 제목 주소와 페이지 ID 주소를 이관된 Teamspace 문서에 연결합니다. 상대 주소는 원래 패키지의 주소를 기준으로 해석하며, 확인한 제목 절 링크는 대상 절로 이동합니다. 추가 이관과 변경분 반영에서는 이미 옮긴 페이지도 찾습니다. 첨부 링크는 본문이 지정한 원본 페이지를 기준으로 연결합니다. 대상을 확정하지 못하면 **이관 검토 진단 → 원본 상세 보기**에서 해당 원문과 관계를 확인할 수 있습니다. [본문 링크 이관](docs/API.md#검토한-원본-이관-적용)

Confluence 체크리스트는 완료 여부를 편집할 수 있는 문서 체크리스트로 옮깁니다. 원본 담당자 표시와 기한은 체크리스트에 텍스트로 보존합니다. 이전 이관에서 문서 전체가 원문 코드 블록으로 저장됐다면, **기존 Confluence 문서 변경분 반영**에서 같은 원본 버전과 본문을 다시 검토해 복구할 수 있습니다. 팀이 수정한 본문은 보존합니다. [오프라인 이관 리허설](docs/PILOT.md#오프라인-원본-이관-리허설)

## 검사

```bash
npm test
npm run typecheck
npm run build
```

`npm run test:browser`는 소스 사본·임시 데이터·별도 웹/API 서버를 준비하고 종료 후 정리합니다. 기본 검사 포트는 웹 5179·API 5189이며, 개발 데이터는 사용하지 않습니다. Chromium이 없는 환경에서는 `npx playwright install chromium`으로 준비하거나 `CHROMIUM_PATH`를 지정합니다. 이미 실행한 검사 전용 서버를 사용하려면 `TEAMSPACE_TEST_URL`을 지정합니다. 이 경우 해당 서버에서 검사 자료를 생성·정리하므로 운영 서버 주소를 사용하지 마세요.

서버 검사는 임시 데이터 디렉터리와 로컬 모의 GitLab을 사용합니다. 실제 기존 서비스를 변경하지 않습니다. API 계약과 첫 구현의 제한은 [서버 문서](server/README.md)에 정리되어 있습니다.

## 구성

```text
app/                 웹 진입점과 공통 스타일
src/Workspace.tsx    프로젝트 개요·탐색·검색·팀
src/features/        티켓·상세·간트·문서
shared/types.ts      웹과 API 공통 모델
server/              독립 API·SQLite·검증·연동
tests/server/        저장·충돌·일정·이관·연동 검사
docs/                범위·구현 상태·검증 기록
```

실제 Jira·Confluence 운영 내보내기 파일의 이관 검증, 문서 매크로와 알림 종류 확장, 시간대별 일정·보고·자동화 확장 등은 목표에 남아 있습니다. 팀 전환 전에는 실제 자료 이관과 운영 시나리오 검증이 필요합니다.
