# Teamspace

팀의 프로젝트, 업무, 일정, 문서, GitLab 활동을 연결하는 독립적인 웹 애플리케이션입니다. Jira·Confluence의 핵심 업무와 Plane·Docmost의 입력·보기·문서 편집 방식을 참고합니다. 해당 제품의 서버나 라이선스 키는 필요하지 않습니다.

초기 대상은 20명 이하 한 팀입니다. 복잡한 보안·SSO·기업용 계정 관리는 현재 범위에 포함하지 않습니다. 기존 운영 도구의 데이터는 자동으로 가져오거나 변경하지 않습니다.

## 로컬 실행

Node.js 24 이상이 필요합니다.

```bash
cd /home/sfa/teamspace
npm ci
npm run dev
```

- 웹: `http://127.0.0.1:5173`
- API: `http://127.0.0.1:5181/api/health`
- 최초 실행 시 두 개의 예시 프로젝트와 가상 팀원·티켓·문서를 생성합니다. 실제 팀 운영 데이터가 아닙니다.
- 웹과 API는 기본적으로 루프백 주소에서 실행합니다. 운영 배포·방화벽·리버스 프록시 변경은 하지 않습니다.
- `API_PORT`, `WEB_PORT`로 개발 포트를 바꿀 수 있습니다. API를 단독 실행할 때는 `PORT`를 사용합니다.

## 현재 구현한 흐름

- 프로젝트 개요와 프로젝트 생성, 작업자 선택, 간단한 팀원·이메일 관리
- 티켓 생성·편집·삭제, 기본 9개와 프로젝트별 사용자 정의 유형, 상태·우선순위·담당자·협력자, 계층·라벨·계획일, 댓글·변경 이력
- 문자·숫자·날짜·선택·다중 선택·확인 여부·팀원·URL 필드, 유형별 적용·필수 입력·보관, 값과 이름의 통합 검색
- 목록/보드, 필터, 상태 변경, 개인 업무 모아보기, 티켓·문서 통합 검색
- 프로젝트별 상태·분류·허용 전이·유형별 필수 속성 설정, 검색·필터·레이아웃의 공유 보기 저장
- 사이클·모듈·릴리스의 책임자·기간·목표일·상태·진행률 관리, 같은 티켓의 일괄 연결·해제
- 같은 티켓을 편집하는 간트, 화면 내 업무 생성·날짜 입력, 스프레드시트 일정 붙여넣기·검토, 막대 이동·기간 조정, FS 연결, 여러 일정 이동의 미리보기·일괄 적용·되돌리기
- 프로젝트 업무 달력·휴무/작업 예외, 검토 후 적용하는 FS 자동 일정 제안, 마일스톤과 변경되지 않는 기준 계획 비교·삭제된 기록 보존
- 문서 트리와 템플릿, 서식·표·체크리스트·코드·이미지 URL, 슬래시 메뉴, 수동 저장과 버전 충돌 보호, 버전 열람·복구
- 문서별로 켜는 Yjs 실시간 공동 편집, 서버 저장 확인·접속자·오프라인 재연결과 복구 충돌 보호
- 문서·업무 참조와 읽기 전용 문서 포함, 접기 블록, 연결/역참조, 제목·서식·구조를 포함한 이력 비교
- 문서 댓글과 업무 연결, 문서 Markdown/JSON 내보내기
- 프로젝트 상태·마감 현황, 기간별 생성·완료·재개 및 일별 흐름 보고서, 저장한 보고서와 연결된 주간 문서
- GitLab 설정과 읽기 동기화, MR/파이프라인의 티켓 키 연결, 인증된 웹훅과 명시적 상태 자동화·미리보기·실행 기록
- 외부 웹훅 수신처·프로젝트/이벤트 범위, 한 번 표시하는 서명 키, 전송 이력·자동 재시도·수동 재시도
- 개인 API 키 발급·회수, 읽기/쓰기·프로젝트 범위·만료 설정과 `/api/v1` 자동화 API
- Jira 관리자/검색 XML·CSV·REST/Importers JSON과 Confluence XML/ZIP 원본의 오프라인 분석·보관, 객체·진단·파일 해시 미리보기와 원문 JSON 내려받기
- 분석한 원본의 프로젝트·작성자·유형·상태·필드 매핑, 변환 검토 후 새 프로젝트에 적용, 원본 이력·관계·첨부 버전 보존
- 실제 파일 업로드·다운로드·문서 이미지 삽입, 전체 워크스페이스와 첨부 바이트의 JSON 내보내기·가져오기, SQLite 영속 저장

기능 구현과 검증 결과는 [개발 상태](docs/STATUS.md)를 확인하세요. [일정·간트 사용법](docs/SCHEDULING.md)과 [API 사용법](docs/API.md)도 제공합니다. 제품 전체의 대체 범위와 완료 기준은 [개발 계획](docs/PLAN.md)에 보존합니다.

## 문서 연결과 비교

문서 도구모음의 **업무 참조·문서 참조·문서 포함**에서 대상을 검색해 삽입합니다. 수동 편집은 문서를 저장하고, 공동 편집은 서버 동기화 표시를 확인하세요. 포함한 원문은 읽기 전용이며 **참조 새로고침**으로 최신 저장 내용을 불러옵니다. 현재 문서의 미저장 편집은 유지됩니다. 연결 탭에서는 참조한 문서와 내 문서를 참조하는 문서를 찾을 수 있습니다.

**접기 블록**은 제목과 본문을 함께 보관합니다. 제목에서 Enter로 본문을 편집하고, 접기·펼치기는 내 화면에만 적용합니다. 펼치거나 접는 동작으로 다른 사람의 화면이나 문서 버전은 바뀌지 않습니다.

이력 탭의 **버전 비교**에서 기준·대상 저장본을 고르거나 **현재 미저장 초안**과 비교합니다. 나란히·통합 보기를 지원하며 서식·표·이미지·참조 대상 변경도 표시합니다. 비교는 읽기 전용이고, 복구는 별도 확인 후 새 버전으로 저장합니다. 포함 블록은 원문을 가리키므로 부모 문서의 과거 이력에 원문 당시 본문을 고정하지 않습니다.

## 보고서와 주간 문서

프로젝트의 **보고서**에서 조회 기간·시간대·업무 유형·담당자를 고릅니다. 현재 업무 현황과 기간별 생성·완료·재개를 각각 확인할 수 있습니다. 수집을 시작할 때 이미 완료된 업무는 현재 현황에 반영되며, 완료 전이는 실제로 관측한 변경부터 집계합니다. 복원으로 이력이 끊긴 기간은 화면에 관측 여부가 표시됩니다.

보고서 화면에서 주간 문서를 만들면 서버가 같은 조건으로 다시 집계하고 결과를 보관합니다. 문서에서 보관본과 관련 업무를 열고 회의 메모를 편집할 수 있습니다.

## 데이터와 연결 설정

기본 데이터 디렉터리는 `data/`이며 `TEAMSPACE_DATA_DIR`로 바꿀 수 있습니다. DB, WAL, GitLab 자격 증명 암호화 키와 원본 분석 파일은 모두 Git 추적에서 제외합니다. DB를 파일 복사로 백업할 때는 API를 종료하거나 SQLite의 일관된 백업을 사용하세요. 자격 증명 복구에는 같은 디렉터리의 `.credential-key`도 필요합니다. 분석 원본은 `data/legacy-imports/`에 비공개 파일로 보관합니다. 이 폴더와 분석 DB 기록은 자체 JSON 백업에 포함되지 않으며, 자체 백업 가져오기 후에도 유지합니다. 필요 없어진 원본은 분석 카드에서 별도로 삭제하세요. 원본 패키지·이력까지 보존하려면 DB와 이 폴더도 함께 일관되게 백업해야 합니다. 원문 미리보기도 현재 신뢰하는 로컬 관리 브라우저 범위에서 접근합니다.

자체 JSON 내보내기는 연결 토큰과 API 키를 제외하며, 가져오기가 성공하면 기존 API 키를 모두 회수하고 자동화 규칙은 비활성으로 복원합니다. 외부 웹훅 수신처·비밀값·전송 기록은 자체 JSON에서 제외하며 가져오기 시 초기화합니다.

기존 티켓의 사이클·모듈·릴리스 문자열은 처음 실행할 때 프로젝트별 계획 항목으로 옮기고 ID로 연결합니다. 원래 이름과 업무 일정·상태는 보존합니다. 구조가 바뀐 업무는 버전을 올려 이전 편집 창의 덮어쓰기를 막습니다. 새 자체 백업은 schema10으로 내보냅니다. 보고서 수집 이력과 보관본, 이관 영수증·원본 기록·업무 관계·첨부 버전 바이트, 업무·문서·일정·연동 설정을 포함합니다. schema1~9 백업도 가져올 수 있습니다. 이전 형식에 없는 설정·기록은 기본값으로 초기화합니다.

상단 팀원 선택은 변경 이력의 작업자를 정하며 인증을 제공하지 않습니다. 실제 팀 운영에 공개하기 전 실행 환경과 단순 접근 제한 방식을 결정해야 합니다.

GitLab은 화면에서 주소·숫자 프로젝트 ID·읽기 토큰을 설정한 후 명시적으로 동기화합니다. 실제 GitLab 자격 증명을 자동 발견하지 않습니다. 토큰은 서버에 암호화해 저장하며 브라우저에 재전송하지 않습니다. 동기화는 GitLab의 업무·저장소 내용을 수정하지 않습니다.

## 검사

```bash
npm test
npm run typecheck
npm run build
```

`npm run test:browser`는 소스 사본·임시 데이터·별도 웹/API 서버를 준비하고 종료 후 정리합니다. 기본 검사 포트는 웹 5179·API 5189이며, 개발 데이터는 사용하지 않습니다. Chromium이 없는 환경에서는 `npx playwright install chromium`으로 준비하거나 `CHROMIUM_PATH`를 지정합니다. 이미 실행한 검사 전용 서버를 사용하려면 `TEAMSPACE_TEST_URL`을 지정합니다. 이 경우 해당 서버에서 검사 자료를 생성·정리하므로 운영 서버 주소를 사용하지 마세요.

서버 검사는 임시 데이터 디렉터리와 로컬 모의 GitLab을 사용합니다. 실제 기존 서비스를 변경하지 않습니다. API 계약과 첫 구현의 제한은 [서버 문서](server/README.md)에 정리되어 있습니다.

## 구성

```text
app/                 웹 진입점과 공통 스타일
src/Workspace.tsx    프로젝트 개요·탐색·검색·팀
src/features/        티켓·상세·간트·문서
shared/types.ts      웹과 API 공통 모델
server/              독립 API·SQLite·검증·연동
tests/server/        저장·충돌·일정·이관·연동 검사
docs/                범위·구현 상태·검증 기록
```

실제 Jira·Confluence 운영 내보내기 파일의 이관 검증, 팀 내 첨부 버전 관리, 사용자 정의 필드의 고급 집계·필터, 문서의 고급 매크로·발행 절차, 시간 단위 일정·작업량 배분·보고·자동화 확장 등은 목표에 남아 있습니다. 현재 개발 버전을 기존 도구의 완전 대체로 간주하지 않습니다.
