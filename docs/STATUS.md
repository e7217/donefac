# 개발 상태

2026-11-20 기준 실행 가능한 개발본에 공동 편집·프로젝트 워크플로·공유 보기, 독립 계획 관리·API 키, 업무 달력·자동 일정 제안·마일스톤·기준 계획·프로젝트 간 작업량, 사용자 정의 업무 양식과 문서 참조·고정 버전 포함·접기·이력 비교·업무 현황과 GitLab 상태 자동화·외부 발신 웹훅, 오프라인 원본 이관, 프로젝트 보고서와 주간 문서, 간트의 스프레드시트 일정 붙여넣기, 티켓 작업 시간 기록·프로젝트 보고서, Jira 작업 시간 이관과 사용자 정의 필드 필터·집계를 구현했다. 전체 제품 목표는 진행 중이다. 복잡한 보안·SSO·기업용 계정 엔진은 최신 사용자 지시에 따라 범위에서 제외한다.

- 전체 서버 회귀 검사 419개와 이관 브라우저의 기존 검사 12개를 통과했다. 추가한 360px 검사에서 기존 문서에 원본 댓글과 이력을 적용하고, 같은 번호의 현재 팀 버전과 원본 저장본을 비교·고정 포함에서 구분했다. 별도 서버 검사에서 현재 페이지 객체가 없는 파일을 이관했고, 영구 삭제한 댓글이 재생성되지 않는 것을 확인했다. 미리보기 충돌, 영수증 저장 실패 시 롤백, 형식 42 휴지통 복원과 독립 파일럿 검사 2개도 확인했다.

최초 계획 이관은 기존 이름·대소문자·공백을 보존하고 바뀐 업무의 버전을 올린다. 자체 백업 가져오기가 성공하면 기존 API 키를 모두 회수하고 자동화 규칙은 비활성으로 복원하며 외부 웹훅 설정·전송 대기·수신 기록을 초기화한다. 트랜잭션 도중 실패하면 기존 키·규칙·수신처·전송 대기도 보존한다. API 사용 범위와 호출 예시는 [API 사용법](API.md)에 기록했다.

일정의 입력·연결·자동 제안·기준 계획과 이전 형식 백업의 동작은 [일정·간트 사용법](SCHEDULING.md)에 정리했다. 업무 양식 사용과 자동화 입력 예시는 [API 사용법](API.md)의 사용자 정의 필드 절을 참고한다. 유형·필드·선택지 이름을 바꿔도 값의 ID는 유지되며, 이전 형식의 백업에 없는 업무 양식은 기본값으로 초기화한다. schema5·6의 달력·마일스톤·기준 계획과 schema6의 업무 양식은 보존한다. 참조·포함·접기 블록은 schema7 이상 자체 백업과 문서 JSON 형식 2에 보존한다. 업무 목록은 자체 백업 형식 20과 문서 JSON 형식 3부터, 업무 현황은 자체 백업 형식 22와 문서 JSON 형식 4부터 보존한다. 고정 버전 포함은 자체 백업 형식 26과 문서 JSON 형식 5에 기록한다. 전체 백업은 원본의 활성 이력과 휴지통 이력을 함께 복원한다. 공동 편집 형식 1~4는 Yjs 데이터를 유지한 채 프로토콜 5로 원자적으로 이전한다. 이전 형식의 미전송 편집은 읽기 전용으로 열고 원하는 보관 데이터를 새 사본으로 복구할 수 있다.

자동 제안은 30분 유효한 서버 기록을 검토 후 적용하며, 적용 결과는 7일간 보관해 재시도로 날짜가 두 번 바뀌지 않도록 한다. 업무·이력·되돌리기·적용 기록은 같은 트랜잭션에 저장한다.

## 현재 한계

- 이력 비교 한도는 본문 JSON 8MiB·별도 제목 64KiB·30,000개 노드·구조 깊이 256이다. 반복이 많은 문서는 계산 한도에 도달한 구간 전체를 삭제/추가로 표시할 수 있으며 동일하다고 생략하지 않는다. 한 화면은 최대 60행이고, 변경 없는 부분과 구조 상세는 명시적으로 펼친다.

- 최신 원문을 가리키는 포함은 참조 새로고침 때 갱신한다. 표시 한도는 포함 5단계·구조 60단계·확장 노드 합계 최대 4,000개다. 검토본과 발행본에서는 해당 블록의 저장된 참조 이름과 ID를 보여준다. 고정 버전 본문은 포함·업무 목록·업무 현황 등 동적 블록의 당시 이름과 설정을 표시한다. 본문에 삽입한 외부 이미지는 해당 주소에서 제공하는 파일을 표시한다. 휴지통에서 원본을 영구 삭제하면 고정 버전 조회 불가 안내가 표시된다. 고급 데이터베이스 매크로는 개발 범위에 남아 있다.
- 업무 목록과 업무 현황은 한 문서에 합계 30개까지 추가할 수 있다. 목록은 전체 개수와 최대 20개 업무의 현재 상태·담당자를 보여준다. 현황은 현재 업무를 집계하고 그룹과 티켓을 페이지로 나눠 표시한다. 목록과 펼친 그룹 안의 티켓은 프로젝트 업무 순서대로 표시한다. 참조 새로고침으로 최신 정보를 불러오며 문서 버전은 그대로 유지한다. 저장한 보기가 삭제되면 해당 블록의 이름과 오류를 표시한다. 검토·발행본은 저장 당시의 범위와 집계 기준을 보여준다. 날짜별 집계를 고정해서 문서와 연결할 때는 기존 주간 보고서 보관본을 사용한다.
- 검토는 요청당 지정한 팀원 1명을 대상으로 한다. 검토함에는 현재 배정·수정 요청 상태가 표시되며, 이전 발행본은 문서 이력에서 확인한다. 배지는 현재 작업자 기준으로 앱을 열거나 전경으로 돌아올 때, 검토 상태를 바꿀 때와 전경에서 30초마다 조회한다. 본문의 삽입 이미지는 저장한 파일 버전을 참조한다. 일반 첨부 주소는 휴지통에서 복원하면 다시 열리고, 고정 버전 포함은 저장본에서 직접 참조하는 같은 문서의 보관 이미지를 계속 읽는다.
- 팀 알림은 상단의 앱 내 알림함에서 조회한다. 업무 댓글은 담당자·협력자·개별 및 프로젝트 구독자, 문서 댓글은 작성자·개별 및 공간 구독자에게 보낸다. 배지는 전경에서 30초 간격으로 갱신하며 목록은 한 번에 50개를 조회한다. 대상이 휴지통에 있는 동안 개별 구독이 보관되고, 영구 삭제하면 제거된다. 기존 알림 기록은 유지된다. 이메일·외부 알림은 남아 있다.
- 공동 편집은 문서별 명시적 활성화 방식이다. 본문은 자동 동기화하고 제목·상태·상위 문서는 별도 저장한다. 원격 커서와 텍스트 선택은 같은 문서·편집 세대에서 지원하는 브라우저끼리 공유하며 포커스를 잃거나 연결을 닫으면 표시를 지운다. 위치 갱신이 30초간 없으면 만료된다. 슬래시 블록 메뉴는 수동 편집에서 제공하며 공동 편집에서는 서식 도구모음을 사용한다. 업데이트 1MiB·문서 JSON 8MiB·누적 Yjs 상태 16MiB 한도가 있다.
- 사용자 정의 필드는 문자·숫자·날짜·단일 선택·다중 선택·확인 여부·팀원·URL을 지원한다. 양식 표시 조건의 기준 값은 확인 여부나 단일 선택을 사용한다. 수식 계산은 남아 있다. 필수 여부는 값의 존재를 검사하므로 숫자 0과 확인 여부 false도 유효하다.
- 자동 일정은 FS·SS·FF·SF 관계와 양수·음수 간격을 근무일 단위로 계산한다. 기간 산정에 필요한 날짜나 선행 연결 날짜가 없거나 완료·취소 업무의 고정 일정과 충돌하면 전체 적용을 막는다. 자동 계산은 프로젝트 10,000개 업무, 한 번 적용은 1,000개 변경, 개별 기간은 3,650근무일까지다. 공휴일은 날짜 예외로 직접 입력한다.
- 시간 배정은 서울 시간의 일별 화면과 서버의 분 단위 UTC 시각을 사용한다. 최대 24시간을 배정하며 날짜 단위 일정·계획 작업량·실제 작업 시간을 각각 관리한다. 겹친 배정을 저장하려 하면 충돌한 업무를 표시하고 입력을 보존한다. [팀원 시간 배정](SCHEDULING.md#팀원-시간-배정)
- 과부하 일정 조정은 프로젝트 안 또는 전체 프로젝트의 작업량을 기준으로 과부하에 기여한 업무를 표시 기간과 마감일 안에서 뒤로 이동한다. 업무의 근무일 수·담당자·계획 시간과 연결을 보존한다. 이동할 수 없는 일정의 초과는 남은 목록에 표시한다. [과부하 일정 조정](SCHEDULING.md#과부하-일정-조정), [프로젝트 간 과부하 조정](SCHEDULING.md#프로젝트-간-과부하-조정)
- 프로젝트별 담당자 작업량은 최대 180일을 계산한다. 기본 가용 시간은 근무일당 480분이며 조정할 수 있다. 주 담당자에게 작업량을 합산하며 프로젝트별 가용 시간과 비교한다. 프로젝트 간 작업량 화면은 14일씩 조회하고, 서버는 요청당 최대 180일·100개 프로젝트·10,000개 대상 업무·36,000개 팀원과 날짜 조합·100,000개 날짜별 업무 배분을 지원한다. 실제 작업 기록을 사용한 계획 자동 조정은 남아 있다.
- 계획 이동은 계획 한 개와 연결 업무를 대상으로 한다. 이동량은 최대 3,650일이며 업무를 포함할 때 연결 업무 1,000개, 프로젝트 업무 10,000개까지 검토한다. 마일스톤의 달성 여부는 수동으로 관리한다. 마일스톤과 업무의 계획 이동은 각각 다루며, 기준 계획 차이는 종료일의 달력일 차이로 표시한다.
- 휴지통에서 업무·문서와 개별 댓글·첨부를 복원한다. 상위 업무나 문서가 휴지통에 있으면 먼저 복원해야 한다. 다른 프로젝트로 옮겨진 문서의 개별 휴지통 항목은 현재 프로젝트 범위에서 찾을 수 있다. 사라진 이정표·관계나 현재 의존성과 충돌하는 연결은 복원 결과에 표시한다. 업무의 기존 상태·유형·필드 설정이 삭제되면 당시 자료를 휴지통에 유지하고 복원을 중단한다. 상위 항목의 영구 삭제는 개별 휴지통 자료와 본문 이력까지 포함한다. 변경·보고·이관 원본의 기록은 각 기능에 남는다.
- 첨부는 파일당 20MiB, 전체 자체 JSON 패키지는 64MiB−1KiB까지다. 초과하면 내용을 누락시키지 않고 오류를 반환한다. 이관한 파일에도 새 버전을 추가할 수 있다. 첨부파일의 복원과 영구 삭제는 전체 버전에 적용한다. 개별 버전 삭제는 남아 있다.
- 자체 JSON 가져오기와 Jira·Confluence 원본 분석·보존·미리보기를 제공한다. 신규 프로젝트 이관, 기존 프로젝트에 대한 새 Jira 업무·Confluence 문서 추가, 기존 Jira 표준 필드와 Confluence 제목·본문의 변경분 반영, 기존 Confluence 문서의 댓글·이력과 첨부 추가를 지원한다. 기존 Jira 업무의 사용자 정의 필드와 하위 기록 갱신, 원본 권한 차이 검토와 운영 내보내기 파일 리허설은 남아 있다.
- 자동화 API는 읽기/쓰기·프로젝트 범위를 검사한다. 팀 접속 모드의 브라우저용 `/api`는 공용 키로 연 세션을 사용하고, 작업자는 앱에서 선택한다. 전체 기능의 자동화 API는 아직 없다. 연동·자동화·외부 수신처 관리는 브라우저용 관리 경로에서 수행한다. [지원 경로](API.md)
- 새 작업 시간은 분 단위로 직접 입력하며 기간 집계는 최대 92일이다. Jira 원본 이관은 매핑된 작성자의 초 단위를 유지한다. 기준 불명확·미매핑 시간은 원본에 보관한다. 이미 적용한 영수증의 소급 반영과 운영 원본을 사용한 검증은 남아 있다.
- 보고서는 최초 실행과 복원 이후 업무 변경부터 관측한다. 원본 이관은 이관 시점의 업무 상태로 시작한다. 조회 기간은 최대 92일, 한 번의 결과는 최대 5,000개 업무, 저장 목록은 최근 100개다. 문서에는 중요도 순으로 최대 30개 업무를 참조하고 전체 결과는 보관본에서 확인한다.
- 필드 집계는 조회 시점의 현재 값과 선택 업무 최대 10,000개를 대상으로 한다. 다중 선택은 선택지마다 업무 수를 집계하므로 그룹별 업무 수를 더하면 전체 업무 수보다 클 수 있다. 그룹의 업무는 50개씩 조회한다.
- GitLab 수동 동기화는 저장소당 MR 최대 1,000개와 최근 파이프라인 50개를 읽는다. 옵션을 켜면 브랜치 최대 500개와 최근 커밋 최대 100개를 추가로 읽는다. 인증된 Push 웹훅은 마지막으로 확인한 브랜치 상태의 기준이다. Push와 수동 조회는 개발 활동 연결만 저장한다. 상태 자동화는 발생 시각이 검증된 MR·파이프라인 이벤트를 사용한다. 실제 운영 GitLab 연결 검증과 웹훅 자동 등록은 남아 있다.
- 외부 웹훅은 최대20개 수신처·동시4건·요청10초·자동5회(기본5/10/20/40초 간격)·종료 기록30일·전체 전송50000건 한도다. 최소 한 번 전달 방식이므로 수신 측은 같은 이벤트 ID를 중복 처리해야 한다. 원문·댓글 내용·사용자 정의 값은 보내지 않으며 이력 UI는 최근50건, 관리 API는 최대100건이다.

## 다음 개발 범위

1. 사용자 정의 필드 집계, 결정 기록과 후속 업무의 연결 확장.
2. 계획·업무 보기와 사용자 정의 필드 보고서의 확장.
3. 여러 팀원의 장시간 동시 편집과 복구를 실제 환경에서 검증.
4. 자동화 확장.
5. 실제 Jira·Confluence 내보내기 파일로 이관을 리허설하고 권한·누락·연결·작성자·이력·파일 해시를 검토.
6. 실제 팀 접속 환경과 장시간 동시 사용, 운영 데이터로의 배포·복원 검증.

목표의 전체 범위는 [개발 계획](PLAN.md)에 유지한다. 검사 통과만으로 미구현 범위를 완료 처리하지 않는다.
