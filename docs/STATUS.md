# 개발 상태

2026-11-16 기준 실행 가능한 개발본에 공동 편집·프로젝트 워크플로·공유 보기, 독립 계획 관리와 API 키를 추가했다. 전체 제품 목표는 진행 중이며, 현재 버전을 Jira·Confluence의 완전 대체로 판단하지 않는다. 복잡한 보안·SSO·기업용 계정 엔진은 최신 사용자 지시에 따라 범위에서 제외한다.

## 검사 결과

- `npm test`: **33개 통합 테스트 통과**. 기존 검사에 계획 이관·참조·일괄 배정·보관·충돌·이름 변경·이전 백업, API 키 해시·권한·작업자·만료·회수·느린 요청의 회수 처리·가져오기 롤백을 추가했다.
- `npm run typecheck`: 통과.
- `npm run build`: 통과. 문서 편집기 등 일부 청크가 500kB를 넘는 경고는 남아 있으며 빌드 실패는 아니다.
- 전체 브라우저 실행 **35개 통과**. 문서·업무·간트·공동 편집·라우팅에 계획 CRUD·배정·보관·충돌, API 키의 일회성 표시·실제 호출·폐기·작업자 전환 검사를 추가했다.
- 마지막 탐색 보완 후 관련 **15개 시나리오 통과**. 신규 3개를 포함해 현재 브라우저 시나리오는 총 **38개**다. 계획 뒤에 업무 상세가 열리는 경우와 작업자 전환에서 취소는 초안을 보존하고, 승인하면 초안·배정 대기를 실제로 버리는 것을 검사했다.
- 브라우저 검사는 매 실행마다 소스 사본·DB·런타임·캐시와 포트(5179/5189)를 분리한다. 전체 검사 후 서버 종료와 임시 디렉터리 삭제를 확인했다. 기존 개발 데이터는 사용하지 않는다.
- 로컬 예시 자료는 프로젝트 2개·티켓 12개·문서 4개다. 브라우저 검사마다 생성한 고유 합성 자료는 정리한다.
- 실제 화면: [프로젝트 개요](screenshots/overview.png), [간트](screenshots/gantt.png), [문서](screenshots/documents.png), [워크플로 설정](screenshots/workflow.png), [두 사용자의 공동 편집](screenshots/collaboration.png), [계획 관리](screenshots/planning.png), [API 키](screenshots/api-keys.png).

실제 GitLab 운영 서버와의 연결, 여러 팀원의 장시간 동시 사용, 대규모 원본 자료의 이관 및 운영 복원 훈련은 아직 검증하지 않았다. 현재 GitLab 검사는 로컬 모의 서버를 사용한다.

최초 계획 이관은 기존 이름·대소문자·공백을 보존하고 바뀐 업무의 버전을 올린다. 자체 백업 가져오기가 성공하면 기존 API 키를 모두 회수하며, 트랜잭션 도중 실패하면 기존 키도 보존한다. API 사용 범위와 호출 예시는 [API 사용법](API.md)에 기록했다.

## 현재 한계

- 공동 편집은 문서별 명시적 활성화 방식이다. 본문은 자동 동기화하고 제목·상태·상위 문서는 별도 저장한다. 커서·선택 영역 공유는 아직 없다. 슬래시 블록 메뉴는 수동 편집에서 제공하며 공동 편집에서는 서식 도구모음을 사용한다. 업데이트 1MiB·문서 JSON 8MiB·누적 Yjs 상태 16MiB 한도가 있다.
- 워크플로 규칙은 기존 티켓 속성에 적용한다. 새로운 사용자 정의 필드·유형과 사용 중 상태를 다른 상태로 일괄 이관하는 기능은 아직 없다.
- 간트는 수기 일정이다. 주말 제외 일괄 이동은 제공하지만 공휴일 달력·마일스톤·기준 계획·자동 일정은 아직 없다.
- 계획 항목의 기간·목표일과 개별 티켓 일정은 별도로 관리한다. 계획 상태 변경이 업무 상태를 바꾸거나 일정을 자동 이동하지 않는다. 마일스톤·기준 계획·자동 일정과의 연계는 다음 범위다.
- 삭제는 현재 영구 삭제이며 휴지통은 아직 없다.
- 첨부는 파일당 20MiB, 전체 자체 JSON 패키지는 64MiB−1KiB까지다. 초과하면 내용을 누락시키지 않고 오류를 반환한다. 첨부 버전은 아직 없다.
- 자체 JSON 가져오기를 제공하지만 Jira·Confluence 원본을 변환하는 이관기는 아직 없다.
- 자동화 API는 [지원 경로](API.md)에서 읽기/쓰기·프로젝트 범위를 검사한다. 브라우저용 내부 `/api`와 작업자 선택은 로그인 기능이 아니다. 외부 발신 웹훅과 전체 기능의 자동화 API는 아직 없다.
- GitLab MR 읽기는 저장소당 최대 1000개, 파이프라인은 최근 50개다. 역순 이벤트·연결 변경 중 동기화 등 다중 클라이언트 정합성과 연동 범위는 추가 보완 대상이다.

## 다음 개발 범위

1. 사용자 정의 필드·유형과 계획·업무 보기의 확장.
2. 공동 편집의 커서·선택 영역 공유, 실사용 장기 동시 편집과 복구 검증.
3. 문서 포함·접기·티켓 참조 블록, 주간보고·결정기록과 문서 이력 비교.
4. 마일스톤·기준 계획·업무 달력·붙여넣기와 검토 후 적용하는 자동 일정.
5. 휴지통·첨부 버전, 알림·보고·시간 기록·대시보드·자동화.
6. Jira·Confluence 원본 이관과 손실·연결·작성자·이력 검증.
7. 실제 팀 시나리오·동시 사용·운영 배포·백업 복원 검증.

목표의 전체 범위는 [개발 계획](PLAN.md)에 유지한다. 검사 통과만으로 미구현 범위를 완료 처리하지 않는다.
