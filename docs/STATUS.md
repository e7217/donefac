# 개발 상태

2026-11-16 기준 첫 실행 가능한 개발본이다. 전체 제품 목표는 진행 중이며, 현재 버전을 Jira·Confluence의 완전 대체로 판단하지 않는다. 복잡한 보안·SSO·기업용 계정 엔진은 최신 사용자 지시에 따라 범위에서 제외한다.

## 구현과 검증

| 영역 | 현재 동작 |
| --- | --- |
| 프로젝트·팀 | 프로젝트 생성·개요, 팀원 등록·이메일 변경, 작업자별 변경 기록 |
| 티켓 | 9개 유형, 상태·우선순위·담당자·협력자, 계층·라벨·일정·견적·사이클/모듈/릴리스 문자열, 댓글·이력 |
| 업무 보기 | 목록·보드·필터·상태 드래그, 개인 업무, 티켓·문서 통합 검색 |
| 간트 | 같은 티켓의 직접 생성·날짜 입력·막대 이동·양 끝 기간 조정, 키보드 조정, FS 연결·연결선, 다중 일정 미리보기·적용·되돌리기 |
| 문서 | 프로젝트/공통 트리·템플릿, 서식·표·체크리스트·코드·이미지·슬래시 메뉴, 댓글·업무 연결, 버전 열람·새 버전 복구 |
| 편집 보존 | 낙관적 버전 충돌, 미저장 업무 버퍼 보호, 문서·댓글 초안의 문서/작업자별 보관, 저장 중 입력/탐색 보호, Back/Forward 취소/승인 |
| 첨부 | 실제 업로드·진행률·목록·다운로드·삭제, SHA-256·MIME 확인, 문서 이미지 삽입 |
| GitLab | 설정 전 요청 없음, 암호화된 연결 토큰, MR/파이프라인 읽기 동기화, 인증·중복 제거 웹훅, 티켓 키 연결 |
| 데이터 | SQLite WAL 영속 저장, schema1/2 자체 JSON 가져오기, schema2에 실제 첨부 바이트 포함, 검증 실패 롤백과 가져오기 세대 저널 재시작 복구 |

상단 작업자 선택은 이력 기록을 위한 기능이며 인증 기능이 아니다. 운영 서비스·IP·NPM 경로·외부 배포는 변경하지 않았다.

## 검사 결과

- `npm test`: **10개 통합 테스트 통과**. 재시작 영속성, 버전 충돌, 문서 복구, 관계 순환, 일정 원자성/되돌리기, 첨부 바이트·경로·크기·MIME, 이관 롤백·중단 후 복구, 모의 GitLab을 검사한다.
- `npm run typecheck`: 통과.
- `npm run build`: 통과. 문서 편집기 등 일부 청크가 500kB를 넘는 경고는 남아 있으며 빌드 실패는 아니다.
- `npm run test:browser`: **19개 브라우저 시나리오 통과**. 문서/댓글/첨부/복구, 충돌·작업자 전환, 티켓 CRUD·검색, 간트 입력·이동·기간 조정·되돌리기, 라우팅과 모바일 메뉴를 검사한다.
- 로컬 예시 자료는 프로젝트 2개·티켓 12개·문서 4개다. 브라우저 검사마다 생성한 고유 합성 자료는 정리한다.
- 실제 화면: [프로젝트 개요](screenshots/overview.png), [간트](screenshots/gantt.png), [문서](screenshots/documents.png).

실제 GitLab 운영 서버와의 연결, 여러 팀원의 장시간 동시 사용, 대규모 원본 자료의 이관 및 운영 복원 훈련은 아직 검증하지 않았다. 현재 GitLab 검사는 로컬 모의 서버를 사용한다.

## 현재 한계

- 문서는 수동 저장 방식이며 CRDT 실시간 공동 편집은 아직 없다.
- 상태 목록은 고정이며 커스텀 전이 그래프·유형별 필드 설정은 아직 없다.
- 간트는 수기 일정이다. 주말 제외 일괄 이동은 제공하지만 공휴일 달력·마일스톤·기준 계획·자동 일정은 아직 없다.
- 사이클·모듈·릴리스는 티켓 문자열 속성이다. 별도 계획 엔티티·관리 화면은 아직 없다.
- 삭제는 현재 영구 삭제이며 휴지통은 아직 없다.
- 첨부는 파일당 20MiB, 전체 자체 JSON 패키지는 64MiB−1KiB까지다. 초과하면 내용을 누락시키지 않고 오류를 반환한다. 첨부 버전은 아직 없다.
- 자체 JSON 가져오기를 제공하지만 Jira·Confluence 원본을 변환하는 이관기는 아직 없다.
- GitLab MR 읽기는 저장소당 최대 1000개, 파이프라인은 최근 50개다. 역순 이벤트·연결 변경 중 동기화 등 다중 클라이언트 정합성과 연동 범위는 추가 보완 대상이다.

## 다음 개발 범위

1. 문서의 실시간 공동 편집·접속자·저장 상태와 협업 복구.
2. 커스텀 워크플로·유형별 필드, 저장된 보기, 사이클·모듈·릴리스 전용 관리.
3. 문서 포함·접기·티켓 참조 블록, 주간보고·결정기록과 문서 이력 비교.
4. 마일스톤·기준 계획·업무 달력·붙여넣기와 검토 후 적용하는 자동 일정.
5. 휴지통·첨부 버전, 알림·보고·시간 기록·대시보드·자동화.
6. Jira·Confluence 원본 이관과 손실·연결·작성자·이력 검증.
7. 실제 팀 시나리오·동시 사용·운영 배포·백업 복원 검증.

목표의 전체 범위는 [개발 계획](PLAN.md)에 유지한다. 검사 통과만으로 미구현 범위를 완료 처리하지 않는다.
