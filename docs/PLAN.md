# Teamspace 개발 계획

목표는 Jira·Confluence의 핵심 업무를 대체하고 Plane·Docmost의 빠른 입력·보기·문서 편집 방식을 반영한 독립적인 팀 프로젝트·지식 관리 제품이다. 초기 사용자는 20명 이하이다. 복잡한 보안, SSO, 기업용 계정 관리 기능은 현재 범위에서 제외한다. 기존 Jira/Confluence/Docmost/Plane 운영 데이터와 서비스는 변경하지 않는다.

## 제품 범위

- 티켓: 기본 9개와 사용자 정의 유형, 담당자·협력자, 상태·전이, 우선순위, 계층·연관, 댓글·첨부, 실제 작업 시간 기록·집계, 사용자 정의 필드·유형별 필수 입력, 변경 이력, 검색·필드 조건·저장 보기.
- 계획: 목록·보드·간트에서 같은 티켓 사용, 인라인 일정 입력·수정, 스프레드시트 일정 붙여넣기, FS·SS·FF·SF 연결과 근무일 간격, 다중 일정 이동·되돌리기, 마일스톤·달력·기준 계획.
- 지식: 문서 트리, 서식 편집·표·체크리스트·코드·이미지, 문서/티켓 참조, 템플릿, 버전 이력·복구, 댓글·검색, 공동 편집.
- GitLab: 저장소·브랜치·MR·커밋·파이프라인 연결, 검증된 웹훅·재동기화, 명시적 상태 자동화.
- API·자동화: 공개 API 계약, 개인/자동화용 API 키 발급·회수, 외부 웹훅과 도구 연결. 복잡한 계정 체계와 별도로 간단한 연동 수단을 제공한다.
- 데이터: 실제 서버 저장, 버전 충돌 검사, 문서·티켓·관계 내보내기, 기존 도구 이관, 백업·복원.
- 팀: 간단한 팀원 관리·작업자 기록, 담당자 배정·댓글·문서 검토 알림. SSO와 복잡한 권한 엔진은 제외.

## 구현 원칙

하나의 저장소에서 웹 UI, 독립 API, 공통 타입을 관리한다. 초기 로컬 개발은 Node 24와 SQLite WAL을 사용하며 UI의 localStorage를 데이터 원본으로 사용하지 않는다. 저장 형식·API·일정 규칙은 참고 제품이나 화면 라이브러리에 종속시키지 않는다. 기존 설계의 PostgreSQL 도입은 규모·운영 요구 검증 후 판단한다.

파일럿은 빌드한 정적 웹, SQLite API와 공동 편집을 단일 Node 주소로 실행한다. 물리 백업은 파일럿과 같은 데이터 잠금을 사용해 식별 키, 첨부, 이관 원본과 저장소를 함께 보관한다. 별도 데이터 경로로 복원하고 실제 브라우저와 로컬 모의 GitLab을 사용하는 합성 리허설로 확인한다. 실제 팀 접속 경로 및 운영 데이터 적용은 환경이 정해진 뒤 검증한다.

20명 합성 리허설은 20개의 브라우저 컨텍스트에서 공동 편집과 티켓·간트 사용을 함께 실행한다. 같은 편집 세대로의 재접속, 복원 이후 이전 편집의 사본 저장, 프로세스 재시작과 별도 경로 복원 뒤의 문서 일치를 검증한다.

업무와 문서의 첨부는 고정 ID를 유지하고 각 파일 버전의 바이트를 따로 보관한다. 목록에서 최신 파일을 선택하고 이력에서 당시 파일을 내려받는다. 문서에 삽입한 이미지는 저장 당시 파일 ID를 참조한다. 버전 추가는 확인한 최신 ID가 여전히 일치할 때 진행하며, 파일과 메타데이터는 장애 후 복구할 수 있도록 함께 반영한다. 자체 JSON과 파일럿 전체 백업에 이력을 포함한다.

업무와 문서를 휴지통으로 보내면 일반 조회·검색에서 사라지고 댓글·첨부 버전·연결과 문서 이력을 함께 보관한다. 복원은 원래 ID와 업무 키를 유지하며 편집 버전과 공동 편집 세대를 갱신한다. 상위 항목을 먼저 복원하고, 상대가 아직 휴지통에 있는 연결은 두 항목이 모두 돌아올 때 복원을 시도한다. 새 생성과 복원을 보고서에서 구분한다. 보관본은 전체 백업에 포함하며 휴지통에서 별도로 영구 삭제할 수 있다.

공동 편집 문서는 Yjs 상태를 원본으로 삼고 JSON·검색용 평문을 같은 트랜잭션에서 생성한다. 복구·가져오기는 편집 세대를 바꾸어 오래된 오프라인 편집을 분리한다. 문서 참조는 ID를 유지하고 포함 본문은 원본을 읽기 전용으로 표시한다. 포함 관계의 순환은 저장·복원·가져오기·공동 편집에서 같은 규칙으로 거절한다. 이력 비교는 제목·본문과 서식·속성·블록 구조를 보존하며, 대규모 비교도 유한한 계산량으로 수행한다.

공동 편집의 커서와 텍스트 선택은 Yjs 상대 위치로 공유하고, 같은 문서와 편집 세대의 수신자가 화면에 표시한다. 서버가 접속자 정보를 제공하고 브라우저가 그 위치를 현재 편집기에 연결한다. 본문 저장과 커서 통신은 별도로 처리하며, 본문 변경을 저장한 뒤 새 위치를 보내고 연결 종료나 유효 시간 만료 시 표시를 지운다.

문서 업무 목록은 프로젝트와 선택한 공유 보기의 ID를 저장한다. 편집 화면에서는 보기의 필터를 적용한 현재 업무와 상태·담당자를 최대 20개까지 보여주며 원래 업무를 열 수 있다. 이력과 검토·발행본에는 당시 저장된 목록 설정을 보존한다. 공유 보기가 삭제되면 그 설정의 이름과 오류를 표시한다.

문서 업무 현황은 같은 공유 보기 조건으로 업무를 상태·담당자·우선순위 중 하나로 묶는다. 편집 화면에서 개수와 비율을 읽고 그룹을 펼쳐 실제 티켓을 연다. 현재 수치는 업무 데이터를 갱신할 때 다시 계산한다. 이력과 검토·발행본에는 저장한 범위와 집계 기준을 보존한다.

문서 검토는 요청 당시 서버 저장본을 이력 ID로 고정한다. 지정한 팀원은 발행하거나 수정을 요청하고, 요청자는 철회할 수 있다. 발행 상태는 최신 승인 저장본을 가리키며 편집기는 이후 초안을 계속 저장할 수 있다. 승인 저장본의 제목·본문과 결정 메모는 백업에 보존한다. 작업자별 검토함·요청함과 프로젝트별 발행본 목록에서 고정된 이력을 연다. 상단에 배정된 대기 건수를 표시한다.

팀 알림은 변경과 같은 트랜잭션에 수신자별로 저장한다. 담당자 변경, 업무·문서 댓글과 문서 검토·수정 요청·발행·철회를 알린다. 사용자 본인과 중복 수신자는 제외한다. 알림에서 대상에 이동하고 읽음 여부를 저장한다. 모두 읽음은 목록의 첫 알림까지 적용하여 이후 도착한 알림을 보존한다. 자체 JSON 백업의 15번 형식부터 알림과 읽음 시각을 포함한다.

프로젝트 워크플로는 상태 ID와 집계 분류를 구분하고 모든 업무 수정·일정 API에서 같은 규칙을 적용한다. 공유 보기도 서버에서 버전 충돌을 검사한다.

계획 작업 시간은 업무별 정수 분으로 저장한다. 프로젝트의 근무일과 팀원별 가용 시간을 사용해 간트의 표시 기간에 대한 계획 작업량을 계산한다. 가용 시간 설정은 프로젝트 기본값, 팀원별 기본값, 날짜 예외를 지원한다. 일정 변경 미리보기에서 초과 날짜를 비교하며 초과 여부로 업무 날짜를 자동으로 바꾸지 않는다.

프로젝트 간 작업량은 각 프로젝트의 달력에 따라 배분한 계획 시간을 팀원의 날짜별 합계로 보여준다. 비교 기준으로 팀 근무일과 개인 예외를 적용한 하루 가용 시간을 한 번 사용한다. 기본·팀원별·날짜별 가용 시간과 공통 달력 예외를 자체 백업에 보존한다. 날짜별 배분에서 원래 업무를 바로 연다.

사이클·모듈·릴리스는 프로젝트별 독립 항목으로 관리하고 업무에는 ID를 저장한다. 이름은 참조에서 생성하며, 이름 변경과 일괄 업무 연결도 버전 충돌을 검사한다. API 키는 자동화 경로의 작업자·읽기/쓰기·프로젝트 범위를 고정한다. 복잡한 로그인·SSO 계정 체계는 추가하지 않는다.

간트에서 계획 기간·목표일·업무 연결을 확인하고, 연결된 업무만 보거나 업무를 선택해 연결을 변경할 수 있다. 업무와 계획의 날짜는 각각 저장하며, 목록의 기간 밖 집계로 차이를 확인한다. 계획 일정 저장은 계획 버전을 검사하고 연결 일괄 적용은 계획과 각 업무의 버전을 함께 검사한다. 계획 상세와 간트는 같은 항목 ID로 이동한다.

계획 일정 함께 이동은 지정한 달력일·근무일 수로 계획 날짜와 해당 업무 날짜의 미리보기를 만든다. 업무를 함께 이동할 때 계획 버전, 연결된 업무와 선후행 조건, 관련 설정을 고정한다. 계획·업무 날짜와 이력·되돌리기 기록을 같은 트랜잭션에서 저장하며 원래 미리보기 ID로 적용 결과를 다시 확인할 수 있다.

업무 유형·사용자 정의 필드·선택지는 프로젝트별 고유 ID로 참조한다. 이름 변경은 값을 바꾸지 않으며 사용 중인 항목을 제거해 자료를 잃지 않는다. 입력 종류와 범위·필수 규칙은 서버에서 검사하고 목록·상세·간트·API·백업이 같은 설정을 사용한다. 공유 보기는 형식에 맞는 필드 조건과 결합 방식을 저장한다. 목록·보드와 프로젝트 범위 자동화 조회는 같은 비교 규칙을 적용한다. 저장된 조건이 사용하는 필드·선택지는 보기에서 참조를 해제한 뒤 삭제할 수 있다.

일정은 프로젝트 달력의 근무일로 계산하며 변경은 미리 검토한다. 자동 제안은 업무·달력·의존성·워크플로의 버전을 고정하고, 같은 트랜잭션 안에서 날짜·이력·되돌리기·적용 기록을 저장한다. 스프레드시트 일정은 업무 키로 같은 프로젝트의 기존 업무를 찾고, 현재 날짜와 제안 날짜 및 연결 경고를 검토한 뒤 일괄 적용한다. 기준 계획은 당시 날짜와 달력을 변경하지 않고 보존하며 현재 계획과 비교한다. 마일스톤의 현재 업무 연결과 과거 캡처 기록을 구분한다.

선후행 연결은 관계 유형에 따라 각 업무의 시작일 또는 종료일을 사용한다. 자동 일정은 시작·종료 조건을 함께 만족하면서 근무일 기간을 유지한다. 연결 변경은 버전을 검사하며 이미 만든 일정 제안은 새로 계산한다. 자체 백업 형식 21에 연결 유형과 버전을 보존한다.

GitLab 상태 자동화는 명시적으로 활성화한 규칙과 현재 워크플로의 검증을 함께 적용한다. 수신 이벤트·상태 변경·이력·외부 웹훅 대기는 같은 트랜잭션에서 저장한다. 외부 전송은 서명과 영속 재시도를 사용하며 수신 측은 이벤트 ID로 중복을 처리한다. 자체 백업으로 복원한 규칙은 비활성 상태로 시작한다.

GitLab 연결 미리보기는 현재 입력한 주소·저장소·읽기 토큰으로 저장소별 조회 가능 여부와 티켓 연결을 계산한다. 설정·연결·업무를 읽기 전용으로 확인한다. 실제 수동 동기화에서도 같은 연결 계산을 쓰고, 파이프라인이 MR에서 티켓 키를 가져올 때는 브랜치와 head SHA가 함께 일치해야 한다.

현재 구현 다음에는 계획·업무 보기, 문서의 고급 매크로, 시간대별 일정과 자원 평준화, 알림·보고와 기존 도구 이관을 확장한다. 실제 구현과 검사 결과는 [개발 상태](STATUS.md)에 기록한다.

## 기존 도구 원본 이관

기존 `/api/import`는 자체 백업으로 워크스페이스를 교체하는 기능이다. Jira·Confluence 이관은 별도 흐름으로 구현하며, 기본값은 새 프로젝트/문서 영역에 추가한다. 패키지 분석 → 작성자·상태·유형·필드 매핑 → 변환 샘플과 손실 미리보기 → 명시적 적용 순서다. 오프라인 분석과 원문 보관에 이어 작성자·상태·유형·필드 매핑, 문서 변환, 새 프로젝트 적용을 구현했다.

적용한 영수증의 **이관 결과 대조**에서 당시 원본과 현재 Teamspace 항목의 연결 상태를 확인한다. 원래 Jira 키·원본 ID·제목으로 찾고, 현재 업무·문서를 열거나 보존한 원본 기록을 읽는다. 첨부 버전은 이관할 때 기록한 크기와 SHA-256을 현재 파일 바이트와 비교한다.

주 입력은 Jira 관리자 XML 백업과 별도 첨부파일 묶음, Confluence Server 전체 공간 XML ZIP이다. Jira CSV의 반복 Comment/Attachment 헤더, 검색 XML과 REST/Importers JSON은 별도 형식으로 판별한다. CSV만으로 작성자·전체 이력·첨부 바이트가 보존된다고 판단하지 않는다. Jira 관리자 백업에도 첨부 바이트는 별도이며, JSON Importers 명세를 UI의 완전한 JSON 내보내기 명세로 취급하지 않는다.

원본 인스턴스·객체 종류·원본 ID를 기준으로 Teamspace ID를 매핑하고 원래 키·URL·시각·작성자·원문 해시를 보관한다. 이름만으로 팀원을 합치지 않는다. 이관 영수증과 원본 기록에 원본 신원·변경 이력·첨부 버전을 보존하고, 현재 업무·문서에서 원본을 찾아볼 수 있게 한다. Confluence Page/historicalVersions/BodyContent 관계를 따라 버전을 복원하고, 양쪽 ID를 확보한 뒤 문서/티켓/include 링크를 재작성한다. 모르는 매크로는 원문과 대체 표시·손실 항목으로 남기며 누락 첨부를 자동 다운로드하지 않는다. 제한된 문서/댓글을 팀 전체에 조용히 공개하지 않고 적용 차단 또는 명시적 제외로 보고한다.

서버가 보관한 미리보기 계획에 패키지 해시·매핑 버전·대상 버전을 고정한다. 같은 패키지 재적용은 중복 생성하지 않고, 대상 변경은 충돌로 중단한다. 적용은 DB와 새 첨부 바이트를 복구 가능하게 묶으며 기존 업로드를 전체 교체하지 않는다. `origin:import`를 사용해 상태 자동화와 외부 발신 이벤트를 만들지 않는다. 완료 근거는 개수·원본 ID·작성자·이력·첨부 해시·양방향 링크 대조와 실패/재시작 복구다.

합성 자료로 분석·매핑·적용·복원을 검증한다. 실제 오프라인 패키지 리허설에서는 Jira 관리자 백업 및 별도 첨부파일의 구성, Confluence 6.9.1의 공간 내보내기 범위, 조직별 매크로와 권한, 누락된 자료를 확인해야 한다.

## Jira 작업 시간 이관

Jira 관리자 XML의 작업 기록과 REST·Importers JSON의 개별 작업 시간에서 이관할 업무, 작성자, 작업일, 초 단위 길이를 확인한다. 날짜는 기록에 명시된 현지 날짜를 유지한다. 팀원으로 명시적으로 매핑한 작성자의 기록을 업무의 작업 시간과 프로젝트 보고서에 함께 반영한다. 제한된 기록은 제외하기 전까지 적용을 차단한다. 매핑되지 않은 작성자나 기준이 불명확한 날짜·시간 단위는 원본에 보관하고 확인 항목에 표시한다. 부분 REST 페이지는 진단에 남긴다. [Jira Data Center 작업 기록 API](https://developer.atlassian.com/server/jira/platform/rest/v11003/api-group-issue/), [Jira JSON 작업 시간 예시](https://confluence.atlassian.com/servicedeskcloud/importing-data-from-json-1097176631.html#ImportingdatafromJSON-Worklogs).

적용 건수와 원본에만 보관한 건수를 미리보기와 영수증에 남긴다. 작업 시간과 보관 원본은 다른 업무 데이터와 같은 트랜잭션에 저장하며 원본 ID로 연결한다. 자체 백업은 원본과 정확한 초 단위를 함께 복원한다. 기존에 적용한 이관 영수증과 부분 데이터의 운영 리허설은 따로 검토한다.

## 보고서와 주간 문서 연결

프로젝트 개요는 현재 상태를 집계한다. 기간 보고서와 흐름 차트에는 업무 생성·삭제와 상태 전이를 구조화한 변경 기록이 필요하다. 업무 작업과 같은 트랜잭션에 이전·이후 상태, 당시 분류, 발생 시각, 출처를 기록한다. 수집 시작 전이나 원본 이력의 누락 구간은 보고서에 표시한다.

팀 보고서에 선택한 시간대의 날짜 경계, 완료 업무·완료 전이·재완료 구분, 관측 구간과 일별 상태를 구현했다. 주간 문서를 만들 때 기간·필터·기준 시각·집계·참조 업무를 다시 계산해 보관하고 양방향으로 연결한다. 실제 작업 시간은 티켓에 작성자와 작업일을 저장하고 별도 보고서에서 기간·작성자·업무를 기준으로 집계한다. 이후 결정 기록과 알림의 연결을 확장한다.

필드 집계는 전체 프로젝트 또는 저장된 보기의 현재 조건으로 업무를 선택해 필드 값으로 묶는다. 값이 비어 있는 업무와 필드 대상 유형에 속하지 않는 업무를 각각 표시한다. 숫자 통계와 그룹별 업무 이동을 제공한다. 그룹을 열 때 집계 이후 바뀐 데이터를 확인해 다시 조회할 수 있게 한다.

## 완료 판단

화면 시안이나 좁은 기능 검사만으로 제품 완성을 선언하지 않는다. 실제 실행 상태·저장 및 재시작·핵심 업무 흐름·브라우저 동작·데이터 이동을 검증하고 미구현 범위를 명시한다. 최초 개발 묶음은 제품 전체 완료와 구분한다.
